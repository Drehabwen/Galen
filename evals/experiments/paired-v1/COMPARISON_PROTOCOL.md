# Galen 外部框架对比协议

对比对象可以是通用 Agent、科研工作台或代码型 Agent（例如用户选定的 CodeS、Graal 等），但不比较品牌口号，只比较同一组可复现任务。

## 统一条件

- 同一批 15 张 paired task cards、同一 fixtures、同一模型等级与温度；
- 每个系统只获得任务卡中声明的工具和数据源；
- 正式实验每个 case 重复 5 次，报告 Wilson 95% 下界；
- 记录版本、提交哈希、模型、参数、工具清单和检索时间；
- 外部系统不能接入 Galen 的专有状态文件，Galen 也不能使用对方没有的隐藏提示。

## 首要指标（决定是否可称为更优）

1. **事实保真**：必需事实召回率，目标 100%；
2. **范围控制**：旧课题/已排除范围泄漏率，目标 0%；
3. **修订一致性**：最新时间点、变量和约束是否覆盖旧版本，目标 5/5；
4. **可交付性**：要求的 PDF/数据表/引用链接是否真实生成、可预览、可验证；
5. **证据可追溯**：关键建议的来源链接覆盖率与检索 provenance；
6. **执行效率**：工具调用数、重复调用数、总 token、TTFR P50/P90。

## 结果表达

先展示 P0 硬门槛，再展示效率：

```text
质量门槛通过率 → 证据/产物可验证率 → 工具与 token 成本 → 响应速度
```

只有在事实、范围和交付均不退化时，token 或速度优势才算有效优势。任何系统若声称“无证据”，必须同时给出已覆盖的数据源清单；未接入 CNKI 不得推断中文证据不存在。

## 建议的获奖叙事

> Galen 的优势不是回答更长，而是把研究问题、修订、数据、证据和产物放进可审计的主动状态层；在相同任务和模型条件下，它更少遗忘、更少越界，并能交付可验证结果。
