# Galen 长尾延迟与工具调用评测

日期：2026-08-29

提交基线：`cc32013`

重复次数：每个 case/model/config 5 次，串行执行

## 测试范围

- E03：缺失文件只读一次，随后读取备用输入并写入交付物。
- E07：保留样本量 48、主要结局 FMA-UE、随访 12 周并生成文件。
- E09：生成真实、非空且可在 Galen 内预览的 Markdown 交付物。

所有运行均记录 TTFR、总耗时、模型请求、工具轨迹、Token、文件状态和硬门结果。P95 使用 5 次样本的 nearest-rank 最慢值；K=5 的 Wilson 95% 下界即使全通过也只有 0.566，因此本轮适合做回归筛查，不足以作为发布级稳定性证明。

## 发现的问题

1. E03 旧评分器只检查是否出现过 `read_file` 和 `write_file`，没有检查路径、错误状态和顺序。严格重评分后，Flash 只有 1/5，Pro 只有 3/5，原来的 5/5 是假阳性。
2. 工作区清单提前暴露 `inputs/brief.md` 存在，模型会推断另一路径不存在，并声称已经记录错误，而没有实际调用工具。
3. E09 把 1200 Token 的最终回复预算错误施加到 `write_file` JSON 载荷。最慢运行的第一次 JSON 被截断，路径解析为空并触发完整重写，总耗时达到 23.820 秒。
4. E07 的短期记忆已经完整注入，但普通 Artifact 任务仍暴露目录和读取工具，导致模型重复列目录、重读 `GALEN.md`，产生额外模型回合。

## 实施的改进

- 新增 `required.tool_sequence` 硬门，精确检查工具名、输入片段、错误状态和调用顺序。
- 明确输入路径的定点读写任务由宿主按用户顺序执行只读预检，将真实结果以标准 ToolResult 回放给模型，并从后续工具集合移除 `read_file`。
- 定点路径任务不再展开工作区文件清单，禁止用推断替代真实工具结果。
- 工具载荷和最终回复使用不同 Token 预算：Artifact 工具回合最多 4096 Token，最终文字仍保持 1200 Token 上限。
- 没有显式输入路径的 Artifact 任务只暴露 `write_file`，避免无收益的目录探索和记忆重读。

## 结论

- E03 的可靠性问题已从提示词概率问题转为宿主确定性流程，Flash/Pro 均恢复到 5/5；Flash 平均耗时下降 20%，Pro 下降 29%。
- E03 每次包含一次预期的 missing-file 错误；原始错误数仍保留在记录中，但预期错误不再降低重复可靠性维度。
- E07 Pro 获益最大：平均总耗时下降 37%，P95 下降 36%，平均输入 Token 从 11302 降至 5560。
- E09 Flash 的 JSON 截断重试被消除：工具错误从 1 次降为 0，平均耗时下降 24%，P95 下降 30%。
- E09 Pro 均值基本持平、P95 上升约 5.5%，未超过当前 10% 负优化门槛，但需要在 K=20 中继续观察。
- 当前剩余长尾主要随 Artifact 输出长度变化，而非 TTFR 或无意义工具循环。下一步应加入 Artifact 长度/信息密度评分，而不是继续简单压低最大 Token。
