# Galen 上下文实验指标口径

## 一、先看什么：三项发布硬门

上下文系统不是压缩竞赛。任何效率收益都必须建立在下面三项不退化的前提上：

1. **关键事实保持率**：任务卡中声明的协议号、样本量、核心变量、时间点、文件事实等，逐条保留。指标为 `retained_required_facts / required_facts`，发布门要求 100%。
2. **范围安全与旧事实泄漏率**：当前任务不应带回已归档研究对象、旧结论或旧方案。指标为 `forbidden_hits / runs`，发布门要求 0；PCTX03/PCTX04/PCTX05 属于高优先级隔离任务。
3. **可交付完成率**：最终产物存在、非空、可预览，且满足任务要求。指标为硬门通过率；不能只看最终回答是否“说得像”。

这三项任何一项下降，都不能用“省了 Token”抵消。

## 二、上下文质量指标

| 指标 | 定义 | 当前数据字段/断言 | 建议目标 |
|---|---|---|---|
| 事实召回率 | 必须保留的事实中实际保留的比例 | `context.required_facts`、`retained_facts`、`required_fact:*` | 100% |
| 事实精确率 | 输出中属于当前范围的事实占比；重点看旧事实是否混入 | `forbidden_response_pattern:*`、`forbidden_artifact_pattern:*` | 旧范围泄漏 0 |
| 修订一致性 | 单字段修改后，新值生效，旧值不再作为当前约束 | PCTX02 的 required/forbidden assertions | 5 次重复全部通过 |
| 干扰恢复率 | 加入无关对话后，仍能完成原任务且不引入新对象 | PCTX04 | ≥ 基线的 90%，且无禁词 |
| 摘要骨架覆盖率 | 压缩摘要保留 `Scope / Current work / Pending work / Key files / Tools / Recent requests / Previously compacted / Newly compacted` | `context.summary_field_coverage` | ≥6/8；目标 8/8 |
| 文件事实落地率 | 文件中声明的事实是否进入最终产物，而非只出现在中间对话 | PCTX05、`required_fact:*`、artifact assertions | 100% |

### 需要新增的上下文指标

- **当前范围命中率**：当前 `scope` 中的实体、变量、时间窗在最终产物中的覆盖率。
- **旧范围泄漏率**：归档实体出现在回答或产物中的比例；回答和产物分别统计。
- **冲突保留率**：遇到来源冲突时，原始双值、来源和待复核状态是否完整保留。
- **上下文定位时间**：从任务输入到第一次引用正确项目状态的时间，避免模型先沿旧方向输出一大段再纠正。

## 三、效率指标

效率只在三项硬门通过后比较：

| 指标 | 定义 | 当前字段 | 比较门槛 |
|---|---|---|---|
| Token 压缩率 | `(基线 token - 候选 token) / 基线 token` | `usage.input/output`、`token_change` | ≥30%；若质量下降则无效 |
| TTFR P50/P90 | 首次可用回答的中位/长尾响应时间 | `latency.ttfr_ms` | P90 不恶化超过 10% |
| 总时延 P50 | 从任务开始到交付完成 | `latency.total_ms` | 不恶化；有显著收益才算加分 |
| 模型请求数 | 一项任务触发的模型轮数 | `model_requests` | 不超过任务卡预算 |
| 工具调用数 | 一项任务触发的普通工具调用数 | `tools.calls` | 不超过任务卡预算 |
| 重复调用率 | 相同工具+相同输入的重复比例 | `tools.max_repeat` 及 trace | 不高于基线；目标 0 |

候选运行必须先满足 `context.compactions > 0`。若摘要覆盖为 `0/8` 且压缩次数为 0，应先判定为测试配置未触发候选路径，不能把它算作算法失败或算法收益。

当前实验的直接证据是：`fullpack` TTFR P50 约快 7.9%，但 Token 反而增加约 0.3%，且质量下降。因此这次不能算效率改进。

## 四、可靠性指标

- **单次硬门通过率**：适合定位具体卡片问题，不代表稳定性。
- **Wilson 95% 下界**：正式比较的保守成功率，避免小样本偶然高分。
- **Pass^5**：5 次重复全部成功的概率估计，适合判断“能否稳定交付”。
- **按案例分层**：不能只报总平均；PCTX03 这类范围切换失败会被平均数掩盖。
- **GAI（Galen Agent Index）**：现有综合分使用 capability 30%、repeatability 25%、state safety 20%、delivery 15%、efficiency 10%。它只能做摘要，不得替代硬门和分项指标。

## 五、工具、证据和数据治理指标

这些指标是科研工作台的第二层验收：

1. **检索可核验率**：关键结论中带 PMID/DOI/可点击链接的比例；链接可打开、元数据与正文一致。
2. **证据覆盖率与引用覆盖率**：`grounding.retrieved_required / required_evidence`、`cited_required / required_evidence` 分开报告，不能把“搜到”当成“引用了”。
3. **检索失败恢复成本**：一次外部检索失败后新增的请求、工具调用和等待时间；失败后要有预算熔断。
4. **数据质量识别率**：重复、缺失、单位错误、时间错位、来源冲突被发现并显式标记的比例。
5. **溯源完整率**：关键指标是否同时保留 `rehab_id / timestamp / source / collection_context / quality_status`。
6. **交付可预览率**：产物非空、格式可预览、链接可打开；科研建议必须能回到具体产物或来源。

## 六、正式实验的报表顺序

每次只按以下顺序解读：

1. 硬门：事实、范围安全、产物交付；
2. 按案例成功率和 Wilson 95% 下界；
3. 摘要骨架覆盖和冲突/文件事实保留；
4. Token、模型请求、工具调用和重复率；
5. TTFR/总时延；
6. 证据、数据治理和可预览性；
7. 最后才看 GAI 总分。

## 七、对下一轮 `fullpack` 的验收定义

候选版本只有同时满足以下条件，才允许进入下一轮比较：

- 5 个上下文案例各重复至少 5 次；
- 关键事实保持率 100%；
- 旧范围泄漏率 0%；
- 摘要骨架覆盖至少 6/8，目标 8/8；
- 候选成功率保留度 ≥90%，且 Wilson 95% 下界不低于基线 2 个百分点以上；
- Token 压缩率 ≥30%，或在不牺牲质量的前提下 TTFR P50/P90 有 ≥15% 改善；
- 工具调用不重复、不超预算；
- 工具/数据策略开关完成后，再分别对 PTOOL01–05、PDATA01–05 做同口径 ≥5 次配对。
