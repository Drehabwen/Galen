# 本机 Agent 工具调用日志分析

分析日期：2026-09-24

## 范围与方法

- Codex：扫描 `%USERPROFILE%\.codex\sessions` 与 `archived_sessions` 的 153 个 rollout 文件，并用 `state_5.sqlite`、`logs_2.sqlite` 做数量和运行错误交叉检查。
- Claude Code：扫描 `%USERPROFILE%\.claude\projects` 的 69 个 JSONL，其中 12 个主会话、57 个子 Agent 记录。
- Gemini / Antigravity：扫描 `%USERPROFILE%\.gemini\antigravity\brain` 的 14 个 transcript。
- Cursor 仅发现少量、较旧的运行日志，没有足够结构化工具调用记录，因此未进入深度比较。
- 只统计结构字段、工具名、状态、时间戳和参数哈希；未导出提示词、文件内容、命令正文、凭据或个人数据。

不同 Agent 对“失败”的记录口径不同，跨 Agent 失败率只能用于定位趋势，不能作为严格基准测试。

## Codex

### 调用结构

其余调用包括图像生成 106 次、Web 访问 83 次，以及少量 Google Drive、GitHub 和 MCP 操作。

### 观察

1. **Shell 依赖过重。** 近四分之三操作被压在通用 Shell 中，搜索、读取、编译、进程控制无法在日志层直接区分，降低了可观测性和安全审计精度。
2. **结构化编辑稳定。** `apply_patch` 失败率约 1.1%，明显低于 Shell，说明文件修改走结构化工具是正确方向。
3. **长尾主要来自编译、生成与轮询。** Shell P95 达 21.7 秒；图像生成中位约 28.5 秒；`wait` 大量出现属于异步任务轮询。
4. **存在一定重复调用。** 检出 886 次连续参数完全相同的调用，约占 2.7%。其中包含合理的等待轮询，但也说明可增加“相同命令结果未变化时退避”的机制。
5. **并行利用偏低。** 保守识别到 354 个并行批次，仅约占调用批次 1.1%；多个独立读取和检查仍有合并空间。

### 平台日志

Codex 运行日志共有 169 条 ERROR：RMCP transport 60 条、模型管理 59 条、Session 44 条。主要 WARN 来源是远程控制 WebSocket 423 条、Skill loader 322 条、Responses 重试 56 条。建议优先排查 MCP 连接和模型配置刷新，Skill loader 警告则应去重或降低无效噪声。

## Claude Code

### 调用结构

| 工具 | 次数 | 占比 | 失败率 | 中位耗时 | P95 |
|---|---:|---:|---:|---:|---:|
| `Bash` | 2,114 | 30.1% | 12.1% | 7.3 s | 245 s |
| `Read` | 2,030 | 28.9% | 5.8% | 0.76 s | 7.9 s |
| `Edit` | 996 | 14.2% | 10.0% | 0.06 s | 23.9 s |
| `Grep` | 331 | 4.7% | 1.2% | 0.56 s | 8.3 s |
| `TaskOutput` | 276 | 3.9% | 4.3% | 65.9 s | 282 s |
| `Glob` | 276 | 3.9% | 2.9% | 1.6 s | 11.6 s |

### 观察

1. **读操作比例健康，但 Bash 长尾严重。** Bash P95 超过 4 分钟，TaskOutput P95 接近 5 分钟，长任务和轮询明显拖慢交互。
2. **编辑失败率偏高。** `Edit` 约 10% 失败，通常意味着匹配上下文漂移、文件已变化或目标字符串不唯一；应在编辑前读取局部上下文并缩小补丁。
3. **文献 MCP 有明显故障点。** Semantic Scholar 搜索失败 34/38，详情读取失败 6/7，是最突出的集成异常；PubMed 和 Crossref 相对稳定。
4. **子 Agent 使用明显。** 69 个记录文件中 57 个属于子 Agent，说明 Claude 工作流更偏任务拆分，但也带来较多 `TaskOutput` 等待成本。

## Gemini / Antigravity

### 调用结构

| 工具 | 次数 | 占比 |
|---|---:|---:|
| `view_file` | 2,542 | 39.9% |
| `list_dir` | 1,075 | 16.9% |
| `run_command` | 964 | 15.1% |
| `replace_file_content` | 605 | 9.5% |
| `write_to_file` | 536 | 8.4% |
| `manage_task` | 338 | 5.3% |

### 观察

1. **探索优先。** 文件查看、目录扫描和搜索约占六成，先读后改的行为较稳定。
2. **命令执行是主要失败源。** `run_command` 记录到 298 次失败，约 30.9%；而代码修改事件失败不足 1%。这通常指向 Shell/操作系统差异、命令不可用、工作目录或超时设置不当。
3. **重复调用控制最好。** 仅检测到 6 次连续完全相同调用，显著低于另外两个 Agent。
4. **会话很长。** 14 个会话产生 6,367 次调用，适合自动执行，但需要阶段性检查点，否则单次失误的累计成本较高。

## 安全与高风险模式

基于参数文本模式进行保守检测，Codex、Claude、Gemini 分别出现 329、83、12 个可能涉及进程终止、递归删除、破坏性 Git 或提权的调用。它们不等于真实事故，部分是测试、说明文字或合理清理操作。

建议所有 Agent 统一记录以下字段：规范化工具名、调用 ID、耗时、退出码、错误类别、读写范围、是否可回滚、参数摘要哈希。递归删除、进程终止和破坏性 Git 应额外记录解析后的绝对目标并执行范围校验。

## 优先整改建议

1. **先修 Claude 的 Semantic Scholar MCP。** 失败率超过 85%，继续重试只会浪费调用；修复前默认转 PubMed/Crossref。
2. **为 Gemini 增加命令预检。** 调用前确认操作系统、Shell、命令存在性和工作目录，可直接降低 `run_command` 的约 31% 失败率。
3. **降低 Codex 的 Shell 黑盒比例。** 将文件读取、搜索、编译、进程管理分别归一为结构化事件；Shell 仅保留无法结构化的操作。
4. **统一长任务策略。** 编译、子 Agent、图像生成采用“启动一次 + 指数退避轮询 + 状态不变不重复输出”，减少重复调用和长尾阻塞。
5. **建立本地周报。** 每周输出调用量、失败率、P50/P95、重复率、高风险模式和最差三个集成，避免技术债再次积累。

## 口径限制

- Codex 的嵌套工具通过 `exec` 参数结构识别；批量调用只要整体失败，可能把同批工具都标成失败。
- Claude 的延迟包含部分用户、Hook 或子任务等待时间，长尾不完全等于工具本身执行时间。
- Gemini 缺少稳定的一一调用 ID，失败率使用执行事件统计，少量未配对记录未强行判错。
- 历史覆盖期不同，不能用总量直接评价模型能力，只能评价这台电脑上的实际使用模式。
