## 0. 决策摘要

Galen 的唯一问题定义是：

> **康复科研人员拥有大量真实病例资料，却无法快速把它们变成可比较、可追溯、可分析、可持续更新的科研证据。**

Galen 的一句话定位是：

> **把康复纵向病例转化为可追溯科研证据的工作台。**

Galen 对用户承诺的核心价值是：

> **把病历、影像报告、体表观察和随访资料组织为统一的患者时间轴与病例队列，识别不可比较的数据、缺失信息和证据冲突，形成研究数据集、图表、报告和下一轮采集规范。**

产品层级不可倒置：

1. 顶层对象是 `ResearchProject`，不是患者管理系统。
2. 患者时间轴是研究项目中的纵向证据视图，不是独立临床诊疗产品。
3. 科研交付是目标，现实康复资料是入口，下一轮采集规范是反馈出口。
4. Research Harness 是内部执行机制，不是用户购买 Galen 的理由。

首个专病与研究形态锁定为：

> **脊柱侧弯保守治疗的纵向回顾性病例研究与病例系列研究。**

Galen 不做现有项目的导航站，也不把多个 GitHub 仓库拼成超级应用。RehabScreenLab、rehab-motion-lab、clinical-voice-pipeline、Clinical-Agent-Eval-Lab 和 RehabGPT 作为能力提供者，通过稳定契约接入 Galen。用户只经历一条完整的康复科研工作流。

核心原则：

1. 产品边界由“病例能否成为研究可用证据”决定，而不是由模型、画布、仓库或功能数量决定。
2. 每一项关键观察必须同时绑定患者、时间点、采集/支具状态和来源；缺一项就不能进入严格比较。
3. 先完成病例证据标准化和数据质量审计，再执行队列分析和科研写作。
4. 模型提出行动并生成内容，宿主管理任务状态、事实对象和完成条件。
5. 未核验事实不得进入硬门槛；证据决定是否完成，模型不能自行宣布完成。
6. 只有会改变研究结论或责任边界的歧义才请求最小人工确认；一次确认必须更新全部下游产物。
7. 所有关键产物必须能在 Galen 内查看、验证、反查来源和继续处理。
8. 每一轮研究必须形成下一轮数据采集规范，使科研结果重新改善现实康复数据质量。

P0 冻结边界：在纵向脊柱侧弯病例闭环完成前，不扩展为通用科研 Agent、患者管理 SaaS、多 Agent 平台、自动论文工厂、自动诊疗系统或原始 X 光自动测量系统。

## 1. 产品愿景

康复纵向科研的数据天然分散：初诊记录在病历里，Cobb 角在报告或影像标注里，ATR 和体表观察在表格或照片里，支具依从性在随访记录里，研究结论又被写进 Word。更危险的是，同一名患者的自然站立、支具内、刚脱支具和脱支具后复查数据经常被混在一起。通用 AI 可以生成流畅总结，却无法稳定保证患者、时间、状态、指标与来源之间的关系，更不能证明这些数据何时具备研究可比性。

Galen 要完成的不是“让 AI 更会聊天”，而是：

> 让康复过程中产生的碎片化纵向病例，沿着可追踪的证据脉络成为研究可用病例行、可信队列和可继续更新的科研成果。

北极星链路：

```text
研究问题与队列定义
→ 病例资料接入
→ Evidence / Event / Observation 标准化
→ 时间、支具状态与来源审计
→ 最小人工确认
→ Research-ready Cohort Row
→ 队列分析与科研交付
→ Galen 内预览与证据反查
→ 下一轮标准化采集规范
```

## 2. 产品定位与边界

### 2.1 一句话定位

Galen 是面向康复医学研究者的本地优先纵向证据工作台：把病历、影像报告、体表观察与随访资料转化为统一患者时间轴和研究病例队列，在分析前识别时间、采集状态、来源、缺失和冲突，用最小人工确认完成关键判断，并在 Galen 内交付可反查的研究数据、图表、报告与下一轮采集规范。

### 2.2 首个市场切口

首个可交付闭环只聚焦：

> 研究者创建一个脊柱侧弯保守治疗纵向研究项目，导入 10—100 例病历、影像报告、体表观察和随访资料；Galen 建立患者时间轴，区分自然站立、支具内、刚脱支具与脱支具后状态，审计不可比较数据与缺失信息，经最小人工确认后形成病例队列、数据质量报告、分析图表、科研报告和下一轮采集规范。

P0 只保证一种研究入口：脊柱侧弯保守治疗的纵向回顾性病例研究/病例系列研究。横断面筛查、通用康复前后测、测量可靠性、系统综述和其他疾病可以讨论和形成草案，但不能宣称已具备完整自动执行能力。

首批病例字段：患者标识、性别、出生时间/年龄、骨龄或成熟度、月经状态（如来源报告）、事件日期、采集状态、曲线区域、Cobb 角、ATR、支具与训练信息、依从性、随访状态、来源定位和核验状态。

### 2.3 Galen 不是什么

- 不是通用 ChatGPT 壳。
- 不是 GitHub 项目启动器或仓库中转站。
- 不是通用低代码工作流编排器。
- 不是代码 IDE，也不默认向医生展示代码和日志。
- 不是 EMR/EHR 替代品。
- 不进行自主诊断、治疗决策或患者管理。
- 不把模型输出包装成未经验证的医学结论。
- 不是原始 X 光自动测量系统；P0 只读取来源中已有且可定位的测量值。
- 不是自动论文工厂；论文草稿只是证据链上可选的研究交付物。
- 不是为每家机构从零定制的一次性科研外包系统。

## 3. 目标用户

### 3.1 核心用户

#### 康复临床研究者（P0 唯一核心用户）

- 手上已有 20—200 例康复病例，正在准备回顾性研究、病例系列研究或课题申报。
- 能提出临床问题，但缺乏把纵向病例转化为研究数据的治理和科研工程支持。
- 关心不同时间点和支具状态能否比较、数值来自哪里、哪些病例能进入分析。

#### 康复医学研究生与科研助理（同一工作流的执行者）

- 承担检索、整理、清洗、统计、绘图和写作任务。
- 需要减少重复劳动，同时保留可复现过程。

#### 课题负责人（同一工作流的审查者）

- 需要判断研究进度、证据质量、风险和交付状态。
- 不希望阅读完整 Agent 对话和工具日志。

### 3.2 后续协作用户

- 统计师。
- 导师与共同作者。
- 数据质量、伦理和方法学审查人员。
- 康复筛查与随访执行人员。

P0 是单人本地工作流；多人实时协作不是首发要求。

## 4. 核心用户任务

### JTBD-01：从纵向病例形成研究可用证据

当我拥有一批脊柱侧弯病历、影像报告、体表观察和随访资料时，我希望 Galen 自动建立患者时间轴，区分时间点与支具状态，发现缺失、冲突和不可比较项，并在最小人工确认后形成可进入队列分析的病例行。

### JTBD-02：从临床问题形成可执行研究

当我有一个康复临床问题时，我希望 Galen 明确研究对象、变量、证据需求、产物与边界，并持续执行，直到形成可审查的研究方案。

### JTBD-03：从病例队列形成可复现分析

当我拥有经过核验的病例队列时，我希望 Galen 自动生成数据质量报告、纳入排除记录、清洗与分析脚本，并生成可验证的表格与图形；不可比较或未核验病例不得静默进入主要分析。

### JTBD-04：从文献形成可追踪证据

当我需要回答一个康复科研问题时，我希望关键结论能够回到具体文献、数据或计算结果，而不是只得到一段流畅文字。

### JTBD-05：在一个产品内完成交付

当任务完成时，我希望在 Galen 内直接查看报告、表格、图表、脚本和证据，不必依赖外部编辑器判断是否生成成功。

### JTBD-06：让研究结果改善下一轮采集

当本轮研究暴露出拍片状态、脱支具时长、依从性或指标缺失时，我希望 Galen 自动生成下一轮标准化采集清单，使后续病例更容易比较和研究。

### JTBD-07：理解 Agent 为什么没有完成

当任务停滞或无法交付时，我希望看到缺少的证据、失败的验证、阻塞原因和下一步，而不是等待模型继续漫长思考。

## 5. 产品哲学

### 5.1 前台是工作流，后台是 Harness

用户看到研究委托、证据脉络、节点状态、研究产物和交付就绪状态。用户不需要看到仓库名、MCP 服务器名、Skill 清单、完整工具 Schema、内部 Prompt 或每一轮原始上下文。

### 5.2 宿主状态权威

以下信息必须由 Rust 宿主保存和验证，不能只存在于 Prompt 或模型文本中：

- 任务目标与成功标准。
- 节点依赖和状态。
- 已尝试方向与重复次数。
- 证据和来源。
- 产物及其血缘。
- 验证与评测结果。
- 阻塞原因。
- 交付就绪状态。

### 5.3 证据支持完成

模型输出“已完成”不改变任务状态。节点完成至少要求：

1. 输出契约中的必需产物存在。
2. 必需成功条件具有已接受证据。
3. 工具或代码执行没有未处理错误。
4. 产物可以在 Galen 中打开或渲染。
5. 对应评测规则通过，或明确记录未通过原因。

### 5.4 先编译研究设计，再执行任务

Galen 在执行任何分析前，必须把自然语言研究意图编译为结构化的 `ResearchDesignCompilation`。该对象至少回答：

- 现有数据能够支持哪些研究类型。
- 哪些目标结论不受当前数据支持。
- 研究问题、研究对象、主要结局、比较关系和时间范围是否明确。
- 哪些关键假设可以由数据核验，哪些必须由研究者确认。
- 推荐设计为何优于其他候选设计。

只有关键假设得到确认、阻塞项得到处理且研究契约锁定后，Harness 才进入自主执行。设计编译门不是逐节点审批，而是防止错误研究被高效执行的前置质量门。

### 5.5 自主推进而非逐节点审批

研究契约锁定后，Galen 在任务契约范围内自动推进节点，不要求用户逐个批准。

仅在以下情况暂停：

- 研究范围或核心问题发生改变。
- 需要用户才能提供的数据或判断。
- 即将执行不可逆或外部可见操作。
- 触及诊断、治疗或其他高风险医学责任边界。
- 连续多次没有新增可接受证据，需要最小外部输入。

交付闸门是系统验证，不是人工批准按钮。研究者最终确认用于承担学术判断，不用于弥补运行时缺失。

### 5.6 本地优先与可恢复

- 任务状态和产物优先保存在工作区。
- 应用重启后可以恢复任务。
- 上下文压缩不能导致证据和关键决策丢失。
- 关键编辑和产物应支持版本回退。
- 云同步和多人协作后置。

### 5.7 Galen 是成果的第一渲染器

研究产物的默认消费场所是 Galen，而不是文件管理器、浏览器、Word、Excel 或其他外部应用。外部导出是交付选项，不是完成研究闭环的前置条件。

用户必须能够在 Galen 内完成“产生—预览—追溯—批注—局部重做—验证—签核”的闭环。一个 Artifact 只有在 Galen 中存在可用的内部呈现、能够说明其来源并通过渲染检查时，才可以计入任务完成度。

Galen 预览的不是孤立文件，而是可交互的研究对象：报告声明应能回到证据，图表应能回到数据和分析，数据应能回到处理步骤，代码应能回到运行记录。打开外部应用只作为用户主动选择或不支持格式的降级路径。

## 6. 旗舰端到端场景

用户创建研究项目：

> 整理 10—100 例脊柱侧弯支具保守治疗病例，判断不同时间点 Cobb 角是否具备可比性，形成研究可用病例队列、数据质量报告、纵向分析图表和病例系列研究报告。

Galen 执行：

1. 扫描工作区，识别病例资料、文件关系与潜在患者，不把全部文件塞入模型上下文。
2. 生成 `ResearchDesignCompilation`，锁定队列、主要观察、可比性规则、结论边界和交付物。
3. 将来源资料登记为 `EvidenceItem`，按患者和时间构建 `ClinicalEvent` 与 `Observation`。
4. 对每个观察记录自然站立、支具内、刚脱支具、脱支具后或未知状态，并绑定页码、图片区域或字段定位。
5. 发现同一患者身份冲突、时间顺序冲突、支具状态缺失、单位/曲线区域不明或图文不一致时，进入 `ReviewDecision` 队列。
6. 研究者只确认会改变病例可比性、研究结论或责任边界的最小问题。
7. 一次确认同步更新患者时间轴、观察值状态、`CohortRow`、数据质量报告和下游 Artifact。
8. 只有满足研究契约的病例进入主要分析；其余病例带原因进入排除或待核验集合。
9. 自动执行队列分析、图表和报告，把脚本、运行记录、数据快照和交付物登记为 Artifact。
10. 由 Clinical Evaluation 规则检查来源闭合、时间泄漏、状态混淆、因果越界、结构和可复现性。
11. 在 Galen 内显示患者时间轴、病例队列、数据质量报告、图表与报告，并支持关键声明反查来源。
12. 根据本轮缺失模式生成下一轮标准化采集清单，使新资料可以继续进入同一研究项目。

用户感知是“一项研究持续向前推进”，而不是“多个 Agent 和仓库正在互相调用”。

## 7. 信息架构与主界面

### 7.1 总体布局

Galen 使用稳定外壳与情境化主工作区。研究侧轨、当前任务和整体运行状态保持稳定；中央区域根据用户此刻要完成的工作，聚焦研究设计、当前执行、科研画布、证据追溯或成果预览中的一种。科研画布不是常驻首页，也不应挤压阅读与判断空间。

```text
┌───────────┬─────────────────────────────────────────────────────┐
│ 研究侧轨  │ 顶栏：当前研究 / 探索·设计·执行·审查·交付          │
├───────────┼─────────────────────────────────────────────────────┤
│ 任务      │                                                     │
│ 资料      │ 情境主工作区                                        │
│ 证据      │ 设计编译 / 当前执行 / 科研画布 / 证据 / 成果        │
│ 成果      │                                                     │
├───────────┴─────────────────────────────────────────────────────┤
│ 上下文 / 缓存 / 工具 / 产物 / 运行状态                         │
└─────────────────────────────────────────────────────────────────┘
```

默认焦点按研究阶段变化：

| 阶段 | 默认主工作区 | 科研画布行为 |
| --- | --- | --- |
| 探索 | 研究委托与资料概况 | 不出现 |
| 设计 | 研究设计编译与关键假设 | 只显示计划摘要，不展开完整画布 |
| 执行 | 当前节点、实时回流与新产物 | 后台运行；出现并行、依赖、阻塞或方向调整时建议展开 |
| 审查 | 成果预览与证据追溯 | 点击来源、查看全局血缘或定位缺口时局部/分屏出现 |
| 交付 | 最终报告与 Readiness Gate | 默认收起，仅在检查未通过时定位相关节点 |

系统可以提示用户查看某个工作面，但在用户输入、阅读、批注或对比版本时不得抢夺焦点。用户手动固定的视图优先于自动路由，关闭画布后仍保留一个紧凑的运行状态入口。

### 7.2 左侧研究侧轨

一级入口：`任务`、`资料`、`证据`、`成果`。侧轨底部显示整体研究进度。不得使用仓库名称作为一级入口。

### 7.3 研究决策线程

承担用户研究目标、设计判断、Task Contract 摘要、关键执行事件、节点回流、阻塞与方向调整。它只展示面向研究决策的结论、理由、证据和待确认项，不展示模型内部推理、完整工具输出或每个节点的全部对话，也不作为无限聊天历史容器。

### 7.4 研究设计编译

这是用户从研究意图进入执行任务的第一核心工作面。系统扫描工作区后立即呈现：

- 研究问题、数据范围、主要结局和候选研究类型。
- 数据能够支持与不能支持的结论。
- 2—3 个设计候选及推荐理由。
- 必须由研究者确认的关键假设。
- 可以由宿主或数据工具自动核验的事项。
- 确认后的执行计划预览。

界面不得以空画布等待用户继续聊天；不得展示原始 Chain of Thought；不得把所有变量和方法学问题都变成人工审批。只有影响研究成立、责任边界或实质性路线选择的事项才进入确认队列。

### 7.5 情境化科研画布与证据脉络

这是 Galen 在复杂性需要被解释时出现的标志性工作面，不是自由流程图编辑器，也不是永久背景。它回答的是“研究现在如何推进、为什么停在这里、这个结果从哪里来”，而不是持续证明系统正在工作。

科研画布在以下情境出现：

- 任务契约锁定后，用户主动查看完整执行计划。
- 两个以上节点并行运行，需要理解依赖和汇合关系。
- 节点阻塞、失败、停滞或触发 `pivot_required`。
- 用户从结论、Evidence 或 Artifact 反向追溯其研究路径。
- Readiness Gate 未通过，需要定位缺失证据或未完成节点。
- 用户主动选择“查看研究全貌”。

单节点顺序执行且没有异常时，默认只显示紧凑的当前步骤、进度、最新证据和产物，不展开完整画布。画布出现后可以收起、切换为分屏或由用户固定；系统不能因为节点状态更新而反复打开、关闭或重置用户视角。

每个节点必须显示：序号和标题、当前状态、输入输出摘要、已接受证据数、产物数、阻塞或风险、上下游产物流向。

节点状态：

```text
draft → ready → running → verifying → completed
                     ↘ blocked
                     ↘ pivot_required
```

不再使用 `pending_approval` 作为默认节点状态。

### 7.6 成果预览

成果预览是主工作区的一等视图，不是弹出的文件附件面板。进入审查与交付阶段后，它的默认优先级高于科研画布。界面提供三种模式：

- **画布视图**：在需要时观察节点、依赖、状态和产物流动。
- **成果视图**：沉浸阅读、检查和操作单个或组合产物。
- **分屏视图**：左侧保留画布或证据脉络，右侧实时呈现当前节点产物。

P0 必须高质量呈现三类核心研究对象：结构化数据表、统计结果与图表、研究报告。其他对象提供足以理解和验收的基础只读呈现：

| 研究对象 | Galen 内部呈现 |
| --- | --- |
| 报告、方案与笔记 | 排版文档视图，支持目录、声明定位和批注 |
| CSV、TSV、XLSX 与结构化数据 | 可排序、筛选、分页的数据表与字段摘要 |
| 统计结果 | 指标卡、结果表、置信区间与方法说明 |
| PNG、JPEG、SVG 与科研图表 | 图像查看、缩放、图注、来源数据与分析链接 |
| PDF 与 DOCX | 基础内部文档投影视图；保留原文件用于下载和高保真比对 |
| Markdown、TXT、JSON | 格式化内容、结构树与原始内容切换 |
| Python、R、Typst 与 LaTeX | 基础语法高亮、版本、执行日志和生成结果 |
| HTML | 隔离沙箱中的只读预览 |
| Evidence 与 Run Ledger | 来源卡片、时间线、Token、工具和验证记录 |

P0 可以通过标准化 HTML/JSON 预览表示实现 DOCX、XLSX 等复杂格式的内部阅读；P1 再补齐接近原生应用的版式、交互与编辑保真度。任何 P0 核心交付物都不能要求用户离开 Galen 才能理解和验收，但 P0 不以复刻 Word、Excel、IDE 或专业 PDF 阅读器为目标。

节点运行期间，预览区应支持增量更新：文献卡片、数据质量摘要、统计表、图表和报告章节可以随着 Artifact 版本产生而出现，不等待整个任务结束。

预览必须显示来源节点、生成时间、验证状态、版本和文件路径，并提供：

- 从报告关键声明定位到 Evidence。
- 从图表定位到来源数据、分析代码和运行记录。
- 从处理后数据定位到输入数据与转换步骤。
- 对段落、表格、图表或代码添加批注。
- 针对选中对象发起局部重做，而不是重新运行整项研究。
- 对比版本、恢复旧版本并重新执行交付检查。
- 用户主动选择下载、导出或使用外部应用打开。

默认点击 Artifact 必须在 Galen 内打开；“外部打开”不得作为主按钮。内部渲染失败时，界面必须说明原因、保留原文件访问方式，并将失败送入 Readiness Gate。

### 7.7 底部观测条

默认只显示上下文占用、Prompt 缓存命中、工具调用数、产物数和运行状态。完整日志、上下文分解和工具追踪按需展开。

## 8. 核心领域对象

### 8.1 ResearchProject

一个康复科研项目，是 Galen 的顶层产品对象，关联研究问题、队列规则、病例、资料、证据、任务、分析、产物、采集规范和版本。P0 不以患者列表替代研究项目首页。

### 8.2 CaseRecord

研究项目中的脱敏病例身份与纵向证据容器。它不是电子病历，不承载诊断或治疗决策，只用于将同一研究对象的来源、事件、观察、核验决定和队列状态稳定绑定。

### 8.3 ClinicalEvent

病例中的一次初诊、拍片、体表评估、支具内复查、脱支具复查或其他随访事件。每个事件至少记录事件时间、采集状态、来源集合和核验状态。采集状态只能使用受控枚举：`natural_standing`、`in_brace`、`immediate_out_of_brace`、`out_of_brace_timed`、`surface_assessment`、`unknown`。

### 8.4 Observation

事件中的一个可引用观察，例如 Cobb 角、ATR、Risser、疼痛、功能或依从性。每个 Observation 必须绑定：

- `case_id` 与 `event_id`。
- 指标、区域、值和单位。
- 采集/支具状态。
- `EvidenceItem` 与精确来源定位。
- `verification_status`：`candidate`、`verified` 或 `disputed`。

只有 `verified` Observation 可以进入精确评测硬门槛；只有满足当前研究可比性规则的 Observation 可以进入主要队列分析。

### 8.5 ReviewDecision

记录研究者对患者身份、时间点、采集状态、图文冲突、符号值或其他关键歧义的最小确认。决定必须保存问题、可选项、证据、选择、研究者、时间和影响范围。它是可审计事实对象，不能只存在于聊天消息中；决定变化后必须触发相关 `CohortRow` 与 Artifact 失效和重建。

### 8.6 CohortRow

单病例进入研究队列的标准化结果，记录纳入状态、排除/待核验原因、选用事件与 Observation、派生变量、来源覆盖和版本。`CohortRow` 只能由已登记对象确定性生成，不能由报告文本反向猜测。

### 8.7 ResearchTaskSpec

任务契约是一次长期任务的权威定义。

```json
{
  "task_id": "ais-longitudinal-brace-2026",
  "goal": "将脊柱侧弯支具保守治疗纵向病例转化为研究可用队列并形成研究报告",
  "scope": ["case_ingest", "timeline", "quality", "cohort", "analysis", "report", "next_acquisition_spec"],
  "non_goals": ["临床诊断", "个体治疗建议", "原始X光自动测量"],
  "deliverables": ["cohort.jsonl", "data-quality.json", "analysis.py", "figures", "report.md", "acquisition-spec.md"],
  "success_criteria": [
    {"id": "source_closed", "required": true, "evidence_ids": []},
    {"id": "temporal_state_valid", "required": true, "evidence_ids": []},
    {"id": "cohort_qc", "required": true, "evidence_ids": []},
    {"id": "analysis_verified", "required": true, "evidence_ids": []},
    {"id": "report_rendered", "required": true, "evidence_ids": []}
  ],
  "pause_policy": ["scope_change", "external_effect", "user_only_input"]
}
```

### 8.8 ResearchDesignCompilation

研究设计编译结果是执行前的权威判断，不能只存在于模型回复中。

```json
{
  "compilation_id": "design-ais-brace-longitudinal-v1",
  "research_question": "支具保守治疗病例中，不同随访状态下的Cobb角是否具备可比性",
  "data_scope": ["baseline", "in_brace", "out_of_brace", "cobb", "atr", "adherence"],
  "supported_claims": ["来源内观察描述", "满足状态规则后的纵向变化"],
  "unsupported_claims": ["个体治疗保证", "单病例因果疗效", "混合支具状态的总体改善"],
  "design_candidates": [
    {"type": "longitudinal_case_series", "recommended": true, "reason": "存在多时间点病例资料"},
    {"type": "causal_effectiveness", "recommended": false, "blocker": "缺少对照与统一采集状态"}
  ],
  "critical_assumptions": [
    {"id": "out_of_brace_duration", "source": "case_review", "status": "unresolved"},
    {"id": "primary_outcome", "source": "researcher", "status": "confirmed"}
  ],
  "compile_status": "needs_confirmation"
}
```

`compile_status` 仅允许：`scanning`、`needs_confirmation`、`blocked`、`compiled`、`superseded`。只有 `compiled` 状态可以生成并锁定 `ResearchTaskSpec`。

### 8.9 ResearchNode

```json
{
  "node_id": "04-data-cleaning",
  "title": "数据清洗与编码",
  "objective": "生成可分析数据集与质控报告",
  "status": "running",
  "depends_on": ["03-cohort"],
  "input_refs": [],
  "required_evidence": [],
  "accepted_findings": [],
  "artifact_ids": [],
  "attempt_count": 1,
  "stale_count": 0,
  "blocker": "",
  "next_action": "检查缺失值和变量类型"
}
```

### 8.10 EvidenceItem

证据是支撑一个科研声明、节点完成或交付判断的可引用记录。

```json
{
  "evidence_id": "ev-001",
  "kind": "literature | dataset | calculation | test | review | human",
  "summary": "缺失值比例低于预设阈值",
  "source_ref": "reports/data-quality.json",
  "source_locator": "missingness.total",
  "linked_claims": [],
  "linked_node_id": "04-data-cleaning",
  "accepted": true,
  "confidence": "high"
}
```

### 8.11 Artifact

```json
{
  "artifact_id": "artifact-report-v1",
  "type": "document | dataset | table | figure | code | log | bundle",
  "mime_type": "text/markdown",
  "path": "output/report.md",
  "title": "筛查研究报告",
  "producer_node_id": "06-writing",
  "input_refs": [],
  "evidence_ids": [],
  "claim_links": [],
  "version": 1,
  "viewer_kind": "document",
  "preview_ref": "previews/artifact-report-v1.html",
  "render_status": "ready",
  "verification_status": "passed",
  "review_status": "draft"
}
```

`path` 保存权威原始文件，`preview_ref` 保存供 Galen 渲染的标准化表示。预览表示可以重新生成，不能取代原始产物；批注和签核状态作为独立结构化记录保存，不能直接污染原始证据。

### 8.12 EvaluationReport

记录产物在证据覆盖、方法适切性、数据血缘、安全与责任边界、结构完整性、可执行下一步和可渲染性方面的评测。

### 8.13 RunLedger

记录模型请求、工具调用、耗时、Token、缓存、错误、重试和产物变化。该对象用于诊断和评测，不默认进入模型上下文。

### 8.14 CapabilityAdapter

外部项目和能力通过统一适配器接入：`EvidenceProvider`、`DataProvider`、`AnalysisProvider`、`RecordIngestProvider`、`EvaluationProvider`、`ArtifactRenderer`、`HandoffProvider`。

## 9. Research Harness 运行要求

### 9.1 任务创建与恢复

- 宿主生成 Task ID 和目录。
- 保存并恢复研究设计编译结果、关键假设与研究者决策。
- 仅在设计编译状态为 `compiled` 后创建并验证任务契约。
- 应用重启后恢复节点、证据、产物和阻塞状态。
- 状态损坏时明确阻塞并指出文件，不允许模型猜测恢复。

### 9.2 节点执行循环

```text
加载最小 Context Pack
→ 选择必要能力
→ 模型提出动作或工具调用
→ 宿主执行并记录
→ 接受或拒绝 Finding
→ 检查节点就绪度
→ 完成 / 继续 / 调整方向 / 阻塞
```

### 9.3 停滞与方向调整

- 没有新增已接受证据时增加 `stale_count`。
- 重复同一工具与同一参数不构成进展。
- `stale_count >= 2`：要求结构性调整方向。
- `stale_count >= 4`：停止无效消耗，询问最小外部输入或标记阻塞。

### 9.4 上下文工程

#### 热上下文

- 当前 Task Contract 摘要。
- 当前节点目标、输入、输出和开放标准。
- 最近工具结果和最近已接受证据。

#### 温上下文

- 已完成节点的结构化回流。
- 当前研究的关键假设与决策。
- Evidence Ledger 摘要。

#### 冷上下文

- 原始工具输出。
- 完整文献与数据。
- 历史版本与运行日志。
- 已压缩会话归档。

冷上下文按需检索，不每轮注入。维护顺序是：保持不动、确定性截断旧工具输出、替换为可检索占位符、最后才做摘要压缩。系统提示词、工具 Schema 和稳定记忆保持字节稳定，避免破坏 Prompt 缓存。

### 9.5 工具按需加载

| 节点 | 工具集合 |
| --- | --- |
| 普通讨论 | 无工具或只读检索 |
| 文献 | Literature、PDF、Citation、Filesystem |
| 数据 | Filesystem、Spreadsheet、Code Runner |
| 分析 | Code Runner、Statistics、Figure、Artifact |
| 写作 | Evidence、Document、Citation、Artifact |
| 评测 | Artifact Read、Evidence、Evaluation |

禁止为所有节点固定暴露完整工具列表。

### 9.6 交付就绪检查

任务进入 `deliverable` 前，宿主必须检查：

- 所有必需成功标准均有已接受 Evidence ID。
- 必需 Artifact 存在。
- 代码或数据改变具备验证记录。
- 引用可以解析到来源。
- 产物在 Galen 内渲染成功。
- 没有未解决的阻塞或高风险边界问题。
- 最后一次有效迭代新增了证据或修复了失败标准。

### 9.7 版本与恢复

P0 在每个节点完成时保存状态快照，在正式产物覆盖前保存旧版本，并支持恢复节点状态和 Artifact 版本。P1 支持任务级 Rewind；Shell 和外部系统副作用必须标记为不可回退。

## 11. 功能需求

### 11.1 P0：单任务完整闭环

P0 不是通用医学科研平台。它只需在一个本地工作区内，针对脊柱侧弯保守治疗纵向回顾性病例研究/病例系列研究，跑通“病例接入—时间轴与状态标准化—最小人工确认—研究可用队列—分析与报告—证据反查—下一轮采集规范”的单任务闭环。

P0 默认使用 Python 作为唯一保证的分析执行环境。R 可以作为可选适配能力存在，但不进入 P0 发布阻塞条件。

#### PRD-P0-01 工作区与研究任务

- 选择并记住本地工作区。
- 创建、保存、恢复 ResearchTaskSpec。
- 工作区缺失或不可写时给出具体修复路径。

#### PRD-P0-02 研究委托

- 用户用自然语言描述目标、资料和产物。
- Galen 扫描工作区并生成可见的研究设计编译结果。
- 显示数据能够支持与不能支持的结论、2—3 个设计候选及推荐理由。
- 区分“数据自动核验”与“研究者必须确认”的关键假设。
- 用户可以修改研究问题、主要结局或范围。
- 设计编译通过后生成并锁定任务契约摘要。
- 任务契约锁定后默认自动执行。

#### PRD-P0-03 病例接入与纵向证据标准化

- 支持导入脱敏病历、影像报告、体表记录、随访文件和结构化表格，并保存原始来源定位。
- 在研究项目中建立 `CaseRecord`，将来源按患者、日期与事件组织，而不是仅按文件组织。
- 为每次初诊、拍片、体表评估、支具内复查和脱支具复查建立 `ClinicalEvent`。
- 为 Cobb 角、ATR、成熟度、依从性等字段建立 `Observation`，保留值、单位、区域、采集状态、来源和核验状态。
- P0 不从无标注的原始 X 光图像自动计算 Cobb 角；只能读取来源已有且可定位的测量值。
- 无法可靠匹配患者、时间、曲线区域、单位或支具状态时，必须标记未知或争议，不能猜测补全。

#### PRD-P0-04 最小人工确认与联动更新

- 只将会改变病例可比性、纳入状态、研究结论或责任边界的问题提交人工确认。
- 每个问题显示原始证据、冲突原因、可选项和对下游的影响。
- 用户决定保存为 `ReviewDecision`，不能只写入对话历史。
- 决定变化后，宿主使受影响的 `CohortRow`、分析结果和 Artifact 失效并自动重建。
- 不要求用户逐节点批准；数据自动可核验的事项由宿主完成。

#### PRD-P0-05 研究可用队列与数据质量

- 从病例对象确定性生成 `CohortRow`，并保留纳入、排除或待核验原因。
- 默认禁止混合自然站立、支具内、刚脱支具和未知状态的 Cobb 角进行严格纵向比较。
- 生成病例级与队列级数据质量报告，至少覆盖来源、时间、状态、单位、缺失、冲突和核验状态。
- 未核验候选事实可以用于鲁棒性测试和人工复核，但不得进入精确评分硬门槛或主要科研结论。
- 支持从队列行回到患者时间轴，从观察值回到原始页码、图片区域或结构化字段。

#### PRD-P0-06 证据脉络

- 将已编译的任务生成 3—8 个 ResearchNode。
- 显示依赖、状态、证据数和产物数。
- 节点状态由宿主更新。
- 支持进入节点检查详情，但不要求逐节点操作。
- 科研画布默认不常驻；普通顺序执行使用紧凑状态视图。
- 在并行、阻塞、方向调整、全局追溯和交付缺口场景中提供画布入口或情境提示。
- 用户阅读、输入或批注时不自动抢占焦点，并记住用户的固定、收起和视图位置状态。

#### PRD-P0-07 证据账本

- 保存 Literature、Dataset、ClinicalSource、Calculation、Test、Review 类 Evidence。
- Evidence 可以回到来源文件、ID 或定位字段。
- ClinicalEvent、Observation、ReviewDecision、CohortRow、节点和最终声明可以绑定 Evidence。

#### PRD-P0-08 真实执行

- 支持文件读取、工作区搜索、Python 和受控命令执行。
- 保存脚本、参数、日志、退出码和产物。
- 重复调用和工具错误可观测。

#### PRD-P0-09 产物注册与预览

- 自动识别并注册节点产物。
- 为产物生成统一的内部预览表示，并根据 Artifact 类型路由到对应 Viewer。
- 高质量支持患者时间轴、病例队列表、数据质量报告、统计结果与图表、研究报告五类核心 Viewer。
- 为 PDF、DOCX、代码、日志和证据提供足以理解与验收的基础只读呈现。
- 支持画布、成果和分屏三种查看模式，以及执行期间的增量预览。
- 显示产物来源节点、版本、验证状态和数据血缘。
- 支持声明—证据、图表—数据—代码、结果—运行记录的双向定位。
- 核心 Viewer 支持批注、版本切换和针对所选对象的局部重做；基础 Viewer 的精细交互后置到 P1。
- 导出和外部打开是次级动作，不得作为验收核心产物的必经路径。
- 预览失败时不允许任务进入可交付状态。

#### PRD-P0-10 下一轮采集规范

- 汇总本轮病例中高频缺失、不可比较状态和人工确认原因。
- 生成下一轮标准化采集清单，至少覆盖事件日期、站立/支具状态、脱支具时长、曲线区域、Cobb 角、ATR、依从性和来源要求。
- 采集规范作为版本化 Artifact 保存在研究项目中；新病例导入时可以据此预检。
- 采集规范属于科研数据质量反馈，不是个体诊疗建议。

#### PRD-P0-11 评测与交付闸门

- 提供确定性检查规则。
- 支持 Clinical-Agent-Eval-Lab 规则适配。
- 显示开放成功标准和失败原因。
- 禁止无证据完成。
- 至少检查患者串线、未来信息泄漏、支具状态混淆、来源外数值、未核验事实硬门槛污染和单病例因果越界。

#### PRD-P0-12 性能探针

- 记录请求开始、首个内容、工具开始与结束、最终完成时间。
- 记录输入/输出 Token、推理 Token 和缓存命中。
- 记录重试与退避。
- 调试日志默认不包含 API Key 和敏感原始数据。

### 11.2 P1：专业研究工作台

- XLSX、DOCX 和 PDF 接近原生应用的高保真预览与有限编辑；P0 已保证其内容可在 Galen 内阅读和验收。
- 数据表格选区与变量级操作。
- Artifact 版本对比与 Rewind。
- 文献证据质量分级。
- 研究模板：横断面、回顾性队列、前后测、系统综述。
- 任务与证据的筛选、搜索和导出。
- 复杂任务按需启用独立 Planner，执行器保持独立 Session。

### 11.3 P2：组织与闭环

- 多角色协作与审阅。
- 机构模板和云同步。
- 外部数据源和院内系统适配。
- 向 RehabGPT 或其他执行端发送经研究者确认的 Handoff。
- 研究数据—结论—执行反馈的长期闭环。

## 12. 医学边界与安全

### 12.1 数据边界

- 默认本地保存 API Key 和项目状态。
- 不在 UI、日志或错误信息中回显完整 Key。
- 患者或受试者数据进入外部模型前必须经过明确策略处理。
- P0 不默认上传原始视频、音频或可识别个人信息。

### 12.2 责任边界

- Galen 输出是科研辅助，不是临床诊断或治疗建议。
- 事实、分析推断和建议必须可区分。
- 缺少证据时明确标记不确定性。
- 结论不得超出研究设计、数据和证据支持范围。

### 12.3 执行权限

- 只读操作在任务范围内自动执行。
- 工作区内可恢复写入可按策略自动执行。
- 删除、发布、外部发送、凭据变更和不可逆操作必须单独确认。
- 人类审核不能被模型文本伪造。

## 13. 性能与体验指标

### 13.1 性能目标

在模型服务正常、网络可用的前提下：

- 应用启动到可输入：P95 小于 3 秒。
- 普通 Pro 请求首个有效内容：P50 小于 3 秒，P95 小于 8 秒。
- 单次工具调用后的继续响应：P95 小于 5 秒。
- 简单单节点任务：P95 小于 30 秒。
- 禁止因为默认推理配置或指数重试导致 150 秒无反馈。
- 连续 2 秒无文本时，UI 必须显示当前阶段而不是静默等待。

### 13.2 产品成功指标

北极星指标：

> **每个研究者小时产出的、经过来源核验且满足研究可比性规则的纵向病例行数量。**

P0 结果指标：单病例从导入到 `CohortRow` 的研究者耗时、关键 Observation 来源覆盖率、时间/支具状态错误率、每例关键人工确认数、能够进入主要分析的病例比例、从 Observation 和报告声明回到原始来源的成功率。

P0 护栏指标：患者串线率、未来信息泄漏率、来源外医学数值率、候选事实误入硬门槛数量、支具内/脱支具状态混淆率、单病例因果越界率。任何护栏指标恶化都属于负优化，不能用速度或文本流畅度提升抵消。

工程辅助指标：从研究意图到锁定任务契约的时间、首次有效输出时间、完整任务耗时与 Token、Prompt 缓存命中、每项任务人工中断次数、Artifact 内置预览成功率、代码与结果可复现率、节点无进展循环次数和交付闸门一次通过率。

## 16. P0 发布验收

P0 发布前必须完成以下真实路径：

1. 在无历史状态的环境中启动 Galen。
2. 配置模型并选择工作区，不出现向导循环。
3. 创建一个脊柱侧弯保守治疗纵向研究项目并导入至少 10 个脱敏真实病例。
4. 宿主扫描资料并创建 ResearchDesignCompilation，锁定队列、主要观察、可比性规则、结论边界和交付物。
5. 系统为每例建立 CaseRecord、ClinicalEvent 和 Observation，并保留精确来源定位与核验状态。
6. 系统正确区分自然站立、支具内、刚脱支具、脱支具后与未知状态；未知状态不得被静默猜测。
7. 遇到会改变可比性或研究结论的歧义时，只请求最小人工确认并保存 ReviewDecision。
8. 人工决定变化后，受影响的 CohortRow、分析与 Artifact 自动失效并重建，不要求用户逐节点批准。
9. 每例形成患者时间轴和 CohortRow；排除或待核验病例显示确定性原因。
10. 未核验 Observation 不得进入精确评测硬门槛或主要研究结论。
11. 节点自动执行，并持续产生 Evidence 与 Artifact；普通顺序执行时科研画布不常驻。
12. 出现并行、阻塞、方向调整或追溯需求时画布可以情境化展开，且不抢夺用户当前焦点。
13. 关闭并重启 Galen，病例对象、研究设计、节点、证据、决定、队列、产物和用户视图偏好能够恢复。
14. 工具失败时能够重试、调整方向或明确阻塞；缺少必需证据时模型无法标记完成。
15. Galen 在内部完整呈现患者时间轴、病例队列、数据质量报告、统计图表和研究报告。
16. 用户可以从 Observation 和报告关键声明返回原始页码、图片区域或结构化字段，从图表返回数据、代码和运行记录。
17. 用户可以在 Galen 内完成核心产物的阅读、筛选、缩放、批注、版本切换和局部重做。
18. 系统根据本轮高频缺失和状态问题生成版本化的下一轮标准化采集清单。
19. 新病例进入同一项目后可以复用采集规范并增量更新队列和产物。
20. 在不打开文件管理器、浏览器、Word、Excel 或独立 PDF 阅读器的情况下，用户能够检查并签核核心交付物。
21. 使用现有 10 例已核验病例完成端到端回归，不出现患者串线、未来信息泄漏、来源外数值、支具状态混淆、候选硬门槛污染或单病例因果越界。
22. 探针报告包含耗时、Token、工具调用和缓存数据，不包含 Key、患者身份信息或未脱敏原始资料。

任何一项失败，P0 均不能声明“端到端闭环完成”。

## 18. 当前开放问题

1. CaseRecord、ClinicalEvent、Observation、ReviewDecision 与 CohortRow 的 Rust Schema 是否直接作为前端共享契约生成来源？
2. 支具状态受控枚举是否需要允许机构级扩展，扩展后如何保持跨项目可比性？
3. 哪些病例核验可以通过双模型或规则预审降低单人复核负担，哪些必须由研究者视觉确认？
4. 哪些医学评测可以确定性实现，哪些需要可选的 LLM-as-judge？
5. 研究者最终学术签核应复用 ReviewDecision，还是建立独立 AcademicSignoff？

这些问题应通过真实任务测试决定，不通过增加抽象层提前决定。

## 19. 最终产品定义

> Galen 是把康复纵向病例转化为可追溯科研证据的工作台。它以真实康复资料为入口，以研究可用病例队列和科研交付为目标，以下一轮采集规范为反馈出口。P0 聚焦脊柱侧弯保守治疗：通过 CaseRecord、ClinicalEvent、Observation、ReviewDecision 与 CohortRow 固定患者、时间、状态、指标和来源关系；由领域 Research Harness 管理模型、工具、上下文、评测与长期任务。宿主保存权威状态，未核验事实不能进入硬门槛，证据证明完成，成果在 Galen 内即可预览和反查，并持续改善后续康复数据质量。
