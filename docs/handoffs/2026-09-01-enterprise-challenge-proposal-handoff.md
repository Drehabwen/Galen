# 企业命题赛计划书接手文档：Galen Rehab Intelligence

日期：2026-09-01（Asia/Shanghai）

## 任务目标

为企业命题赛起草两份彼此一致、但职责不同的材料：

1. **企业命题赛计划书**：让企业评委相信团队理解问题，并拥有聚焦、可落地的解决方案。
2. **技术佐证报告**：让评委相信软件、数据协议、评测与验证基础真实存在。

不要把它写成普通“大创项目介绍”，也不要写成泛泛的“AI 康复平台”。

## 一句话定位（不可偏离）

> **Galen Rehab Intelligence：面向运动疲劳恢复的多模态连续评估与康复辅助系统。**

核心洞察：康复 AI 的短板不是缺少单次数据或又一个模型，而是缺少围绕同一个人持续积累、可信、可计算的恢复状态。

对外首个验证场景必须是：**运动疲劳恢复**。

长期底层架构是：**通用连续康复状态系统**。不要在本次材料里扩成脑卒中、术后、慢痛、运动疲劳等多场景大杂烩。

### 正确产品闭环

```text
运动员 / 受试者
  → 康复师工作台（采集、评估、报告）
  → Rehab ID + 统一数据协议
  → Galen（连续状态画像、变化检测、依据解释、报告）
  → Galen Recovery Companion（离场后的睡眠/RPE/疼痛/训练随访回流）
```

## 连续康复状态模型：Rehab State Schema v0.1

系统以人为中心，不以设备或单一指标为中心。一级维度固定为 6 个：

1. **生理恢复**：HRV、心率、睡眠、血乳酸、压力相关指标。
2. **功能能力**：力台、步态、ROM、肌力、动作视觉、功能量表。
3. **症状与风险**：疼痛、疲劳、异常变化、损伤事件。
4. **活动与参与**：训练完成度、日常活动、返训/返校进度。
5. **心理与行为准备度**：RPE、情绪、恐惧回避、依从性、主观恢复。
6. **干预与环境**：训练负荷、治疗记录、家庭训练、场地和照护环境。

横切字段（不是第七个人体维度）：来源、时间点、采集条件、数据质量、证据追溯。

## 计划书写作口径

### 开头可直接使用的叙事

> 在运动训练与康复恢复过程中，HRV、动作表现、力量测试、疼痛、主观疲劳和训练记录往往分散在不同设备与系统中。治疗师和教练看到的常常是一次检查结果，而非一个人在训练负荷、疲劳与恢复之间连续变化的状态轨迹。
>
> 因此，本项目提出 Galen Rehab Intelligence：以运动疲劳恢复为首个验证场景，构建面向个体的多模态连续康复状态系统，将不同来源的数据统一到同一 Rehab ID 和时间轴中，并形成可追溯的恢复画像与辅助决策依据。

### 推荐目录（9 节）

1. 真实场景与企业问题：为什么一次、单指标评估不足。
2. 核心洞察：连续、可信、可计算的状态数据层。
3. 解决方案：Galen Rehab Intelligence 与完整闭环。
4. 关键技术：Rehab ID、状态模型、数据协议、纵向变化、证据追溯。
5. 首个场景：基线 → 疲劳后 → 恢复后的运动疲劳恢复。
6. 可运行 Demo：工作台采集、Galen 解读、Recovery Companion 回流。
7. Pilot 验证：数据来源、时间点、指标和专业复核。
8. 企业适配：企业大模型能力 × Galen 康复状态层 × 康复应用。
9. 现有成果、30 天试点、团队与合作诉求。

### 计划书语言替换

| 不要写 | 改写为 |

| 使用 RAG、多 Agent、向量数据库 | 每项关键结论可追溯到数据来源、时间点和依据链接。 |

| 预测疲劳程度 | 识别个体相对基线的变化与需要进一步确认的恢复状态。 |
| 通用康复平台 | 以运动疲劳恢复为首个验证场景，可扩展到其他连续康复场景。 |

## 技术佐证报告写作口径

技术佐证报告不是商业宣传册。它按“真实能力 → 可复现证据”组织。

### 推荐目录

1. 版本与工程概览：仓库、分支、提交号、构建产物、测试环境。
2. 已实现的软件能力：工作台、Galen、报告、随访。
3. Rehab State Schema v0.1：6 维状态及横切来源字段。
4. 数据接入：设备/量表 → 标准化记录 → Rehab ID → 时间轴。
5. Galen 智能能力：文献依据、可点击链接、信息缺口、交付物预览。
6. 真实演示链：导入三时间点数据 → 状态解释 → 报告预览。
7. 自动化评测：任务合同、禁止编造、产物可预览。
8. Pilot 验证设计：疲劳实验、采集、评价与专业复核。
9. 产品演进：现有设备接入 → 发现数据缺口 → 专用硬件。

每个能力用固定证据格式：

```text
能力名称
→ 用户动作
→ 系统实际输出
→ 截图/日志/测试编号
→ 对应文件或提交号
→ 当前用途
```
