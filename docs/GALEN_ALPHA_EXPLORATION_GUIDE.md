# Galen Alpha 自由探索手册

> **适用版本**：Galen v0.1.2 · Windows 10 / 11 64 位
> **面向对象**：受邀体验者
> **测试目标**：像真实用户一样自由使用 Galen，发现阻塞、误解、错误结果、数据问题和不自然的交互。

---

## 1. 欢迎参与

Galen 是一个面向康复科研的 AI 工作台。它尝试把一个研究目标转成可执行计划，持续推进节点，把文件登记为可追踪的研究产物，并直接在 Galen 内预览。

这次不是考试，也不是产品演示。你不需要证明 Galen 好用，也不需要按照开发者预想的方式操作。

### 最重要的体验原则

1. **按自己的习惯表达**：可以简短、模糊、口语化，也可以一次提出复杂目标。
2. **不要迁就 Galen**：如果你不知道下一步该点哪里，这本身就是问题。
3. **允许改变主意**：追问、补充条件、推翻计划、切换任务，观察 Galen 是否能跟上。
4. **先记录现场，再尝试恢复**：出现异常时先截图和记录，再重试、切换页面或重启。
5. **结果必须由人判断**：模型生成的科研设计、文献结论和统计建议都不能未经核验直接用于临床或正式研究决策。

## 2. 安全边界

Alpha 阶段请遵守以下边界：

- 只使用虚构、公开或已充分去标识化的数据。
- 不输入姓名、身份证号、手机号、住址、住院号、面部图像等可识别患者信息。
- 不让 Galen 代替医生进行诊断、治疗或个体化医疗决策。
- 每位体验者使用自己的 DeepSeek API Key，不共享 Key，也不要把 Key 放进截图、反馈或工作区文件。
- 为体验测试新建独立文件夹，不要选择包含唯一原始数据或重要文件的目录。
- 如果 Windows 阻止安装或运行，请联系测试组织者；不要关闭系统安全功能。
- 如果发现疑似密钥泄露、跨工作区读取、文件异常覆盖或删除，请立即停止操作并按 P0 问题反馈。

> 当前 API Key 保存在本机 `%USERPROFILE%\.galen\models.toml`。Alpha 版本尚未接入 Windows 系统凭据库。

## 3. 安装与首次配置

### 3.1 安装

1. 从测试组织者处获取 `Galen_0.1.2_x64-setup.exe`。
2. 向测试组织者核对安装包文件名和 SHA256，不使用来源不明的安装包。
3. 正常完成安装并启动 Galen。

当前安装包尚未进行 Windows Authenticode 代码签名，Windows 可能提示发布者未知。不要为此关闭 Defender、SmartScreen 或其他系统安全设置。自 v0.1.1 起，Galen 支持自动更新：收到新版本提示后按引导升级即可，无需手动重装。

### 3.2 配置自己的模型

1. 在欢迎向导中选择 DeepSeek V4 Pro 或 Flash。
2. 粘贴自己的 DeepSeek API Key。
3. 保存后运行连接测试。
4. 如果失败，请记录完整错误文字，不要在反馈中附上 Key。

### 3.3 创建测试工作区

建议新建一个空文件夹，例如：

```text
D:\Galen-Alpha\你的名字-日期
```

每个课题使用不同文件夹。Galen 会在工作区中保存任务、节点、记忆和研究产物。

## 4. 界面与工作模式

### 4.1 首次启动：欢迎向导（四步）

启动后进入欢迎向导，按顺序完成：**模型 → 工作区 → 模式 → 环境**。

1. **模型**：选择 DeepSeek V4 Pro 或 Flash，粘贴自己的 API Key 并保存（可跳过，稍后点顶部「模型状态 → 打开设置向导」补配）。
2. **工作区**：选择一个文件夹作为科研项目目录（建议英文路径、每个课题独立文件夹）。
3. **模式**：选择默认工作模式（讨论 / 计划 / 自动）。
4. **环境**：确认连接测试与模型状态，进入主界面。

### 4.2 顶栏

- 左侧显示 **康复科研工作台** 与**当前研究**（当前工作区研究课题）。
- **工作模式切换**（讨论 / 计划 / 自动）：
  - **讨论**：快速提问、梳理概念、只读分析；不会主动写入工作区文件。
  - **计划**：制定方案，列出步骤，确认后执行；先观察 Galen 如何拆解研究任务。
  - **自动**：自主分解目标，并行执行，汇总产出；测试完整闭环。
- **GALEN.md**：显示项目记忆（字节数），悬停可查看记忆内容。
- **模型状态**：管理模型、API Key 与连接状态（绿点 = 密钥已配置）。
- **选择工作区**：切换当前项目文件夹。

### 4.3 研究任务工作台

主界面围绕一条科研任务组织：

- **计划画布**：AI 生成的科研计划节点，可点击查看详情、进入节点执行；确认后开始执行。
- **执行线程**：节点执行进度与当前状态（运行中 / 完成 / 失败），一个节点完成后自动进入下一个。
- **成果画布 / 文档**：节点成果与研究文档的查看区域，Markdown 以结构化方式渲染。
- **产物库**：展示已经登记的交付文件（数量、类型、路径、大小），允许重新打开与预览。
- **康复上下文面板**：当前康复研究相关的背景上下文（人群、干预、结局等）。
- **会话检查器 / Token 用量**：可查看会话结构与 Token 消耗，帮助理解成本与上下文。

### 4.4 证据脉络与成果预览

- **证据脉络**用于观察研究节点、依赖关系和完成状态。
- **成果预览**用于在 Galen 内查看生成的 Markdown 或文本产物（标题、表格、引用均结构化渲染，不是源码）。
- 底部或侧栏**产物库**应展示已经登记的交付文件，并允许重新打开。

## 5. 开始探索

你可以从自己的真实科研困惑开始。如果暂时没有任务，可使用下面的起点：

> 我想研究脑卒中患者居家上肢训练的依从性。请先帮我澄清研究问题，建立三个节点的初步计划，执行当前可以完成的部分，并把简报保存在工作区供我预览。

这只是起点，不是标准答案。接下来可以自由追问、改变要求或换一个完全不同的问题。

### 可任选的探索方向

不必全部完成，也不必按顺序进行。

#### A. 第一次使用是否自然

- 不看说明直接开始，你能否理解下一步？
- API Key、工作区和模式的含义是否清楚？
- 空白页面有没有告诉你可以做什么？
- 错误提示能否告诉你如何恢复？

#### B. 任务理解与计划质量

- 输入一句很短的问题，观察 Galen 会追问还是擅自假设。
- 输入包含多个目标的复杂任务，检查节点是否完整。
- 故意遗漏人群、干预或结局，观察 Galen 如何处理不确定性。
- 计划生成后补充新限制，观察画布和任务是否同步更新。
- 要求删除、合并或重新排序节点，观察旧状态是否残留。

#### C. 执行与流动感

- 节点执行时，你能否看出 Galen 当前在做什么？
- 一个节点结束后，下一个节点是否自然衔接？
- 是否出现长时间无反馈、重复思考或重复调用？
- 中途提出问题，Galen 能否回答后继续原任务？
- 切换讨论、计划和自动模式，行为是否符合模式含义？

#### D. 产物与内置预览

- 明确要求生成一个 `.md` 或 `.txt` 文件。
- 检查成果预览是否**结构化渲染**：标题、列表、引用、表格是否显示正常（而不是整篇源码）。
- 检查产物库是否登记数量、类型、路径、大小，能否重新打开。
- 检查产物标题、路径、内容和所属节点是否一致。
- 再生成第二个同名或不同名产物，观察是否重复、覆盖或混淆。
- 重启 Galen 后，旧产物能否重新找到和预览。

#### E. 记忆与恢复

- 完成一部分任务后关闭并重启 Galen。
- 观察任务节点、聊天记录、产物和工作区是否恢复（v0.1.1 起会话以事件日志持久化，重启应完整恢复）。
- 切换到另一个空工作区，检查旧任务是否错误出现。
- 再切回原工作区，检查状态是否完整恢复。
- 修改研究方向后，观察 Galen 是否仍被旧上下文错误影响。

#### F. 科研可信度

- 检查 Galen 是否把假设写成确定事实。
- 检查引用、PMID、量表名称和统计方法是否真实、适用。
- 询问证据不足的问题，看它是否承认不确定性。
- 给出互相矛盾的条件，看它是否指出冲突。
- 要求说明局限、偏倚和下一步验证方法。

#### G. 边界与异常输入

- 输入错别字、中英文混合、超长文本或只有一句话的任务。
- 请求工作区之外的路径，观察 Galen 是否拒绝。
- 断网或模型服务暂时不可用时，观察错误和重试体验。
- 快速连续点击或重复提交，观察是否产生重复消息和重复文件。
- 把窗口缩小或调整比例，检查文字、按钮和画布是否被遮挡。

#### H. 康复科研与文献检索（v0.1.1+）

- 输入一个康复科研问题（如脑卒中、脊柱侧弯、运动干预），观察 Galen 是否调用 PubMed / `search_rehab_literature` 检索。
- 检查检索结果是否包含 PMID、标题、作者、期刊、年份、DOI，研究类型过滤（RCT / 系统综述）是否可用。
- 让 Galen 对文献做结构化笔记、按证据等级整理、生成引用。
- 检查引用与 PMID 是否真实、可核验，是否错误杜撰。
- 结合康复上下文面板：人群、干预、结局等背景是否被正确纳入计划。

#### I. 自动更新与成本观察（v0.1.1+）

- 观察顶栏或更新管理器是否提示新版本，升级过程是否顺畅、配置与工作区是否保留。
- 打开会话检查器 / Token 用量，观察一次任务的 Token 消耗是否合理、可解释。
- 切换 Pro 与 Flash，观察响应速度与 Token 成本的差异是否符合预期。

## 6. 什么算问题

以下都值得反馈，不限于程序崩溃：

- **阻塞**：无法安装、无法配置、无法发送任务或无法继续。
- **循环**：重复欢迎向导、重复工具调用、重复消息、重复写文件。
- **状态错误**：画布、聊天、任务、节点、产物之间不一致。
- **恢复错误**：重启后丢失、重复执行或加载了其他工作区的数据。
- **产物错误**：文件为空、路径错误、无法预览、绑定错节点或内容被覆盖。
- **科研错误**：虚构引用、方法不匹配、过度结论或忽略关键风险。
- **性能问题**：长时间没有首个反馈、明显卡顿、资源占用异常。
- **可用性问题**：不知道下一步、按钮名称难懂、反馈不明显、布局拥挤。
- **信任问题**：不知道 Galen 做了什么、为什么做、数据保存在哪里。
- **“感觉不对”**：即使无法准确描述，也请记录当时的直觉和上下文。

### 问题优先级

| 等级 | 定义 | 示例 |
|---|---|---|
| P0 | 安全、隐私或数据破坏 | Key 泄露、跨工作区读取、原文件被不可恢复地覆盖 |
| P1 | 核心流程完全阻塞 | 无法启动、无法配置模型、任务永远无法完成 |
| P2 | 结果错误但可以绕过 | 节点状态错误、预览失败、重复执行、明显科研错误 |
| P3 | 体验和表达问题 | 文案难懂、布局不自然、反馈太慢但最终可完成 |

## 7. 出现问题时怎么做

1. **不要立即清空工作区或卸载。**
2. 记录发生时间、当前工作区、模型、模式和思考强度。
3. 复制你刚才输入的原始任务和界面上的完整错误信息。
4. 截取问题页面；截图前确认没有 API Key 和患者敏感信息。
5. 记录最后一个正常步骤和第一个异常步骤。
6. 尝试一次最小恢复动作，例如重新提交、切换标签或重启。
7. 记录恢复后是正常、仍失败，还是产生了重复任务或文件。

如果问题涉及密钥、患者信息、错误工作区或文件损坏，请停止测试，不要继续尝试。

## 8. 问题反馈模板

复制下面内容，每个问题单独填写一份：

```markdown
## [P0/P1/P2/P3] 一句话问题标题

### 环境
- Galen 版本：v0.1.2
- Windows：10 / 11，版本号：
- 模型：DeepSeek V4 Pro / Flash
- 模式：讨论 / 计划 / 自动
- 思考强度：关 / 低 / 中 / 高
- 工作区：新建空工作区 / 已有项目工作区
- 发生时间：

### 我想完成什么
粘贴原始任务，不要改写。

### 复现步骤
1.
2.
3.

### 我预期看到什么

### 实际发生了什么
请包含完整错误文字、等待时长、错误节点或产物路径。

### 发生频率
- [ ] 每次都发生
- [ ] 偶尔发生
- [ ] 只发生一次

### 恢复尝试
我尝试了什么？恢复后是否重复执行、丢失状态或生成重复文件？

### 附件
- 截图：
- 相关产物：
- 其他说明：

### 隐私确认
- [ ] 截图和附件不包含 API Key
- [ ] 不包含可识别患者信息
```

### 好反馈的三个特点

- 保留用户原话，而不是事后总结成“它坏了”。
- 描述可观察事实，例如“等待 96 秒后仍没有正文”，而不是只写“很慢”。
- 写清楚恢复动作及其后果，这能帮助发现重复执行和状态机问题。

## 9. 一次体验结束后

即使没有发现明确 Bug，也请回答：

1. 你最想让 Galen 完成的真实任务是什么？
2. 哪一步最让你困惑或不信任？
3. 哪个结果让你觉得有价值？
4. 哪个操作显得多余、迟钝或打断思路？
5. 你是否愿意下次继续用它推进同一个课题？为什么？
6. 如果只能改一件事，你希望先改什么？

“没有问题”不是测试目标；真实感受、犹豫和绕路同样是产品证据。

## 10. Alpha 阶段已知限制

- Windows 安装包尚未进行 Authenticode 代码签名，可能出现发布者未知提示。
- API Key 当前保存在本机配置文件（`%USERPROFILE%\.galen\models.toml`）中，尚未进入系统凭据库。
- 模型响应受到网络、账户状态和供应商服务波动影响，并产生 API 费用；最近一次发布验证（80 次）中仍捕获到 3 次约 20 秒的首响应尖峰。
- 自动更新自 v0.1.1 起可用；若升级失败或更新源不可达，可从测试组织者处获取新安装包手动安装。
- 真实模型探针已验证任务、节点、Artifact 与预览闭环（80/80 硬门、18/18 交付契约、9/9 质量门），但公开发布所需的干净电脑覆盖测试仍在补充，K=20 样本尚不足以证明 99% 生产可靠性。
- Galen 生成的科研内容必须由具备相应专业能力的人复核。

感谢你帮助 Galen 暴露问题。Alpha 阶段最有价值的产物不是一份漂亮报告，而是一个诚实、可复现的问题。
