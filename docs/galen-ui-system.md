# Galen UI 体系与色彩规范

版本：v0.1  
依据：当前两张高保真原型图  
适用范围：Galen 桌面端科研工作站

## 1. 设计基准

本规范以两种核心界面形态为准：

- `科研执行线程态`：对话驱动科研协作，包含文档选区修订、证据链、版本记录和协作者。
- `日常科研工作台态`：默认常驻形态，展示当前目标、阶段进度、AI 执行状态、下一步建议、最近产物和待签核事项。

设计目标不是做一个医学版聊天工具，也不是做一个密集仪表盘。Galen 的界面应当像一个正式、安静、可审计的科研协作系统：

- Word 式文档画布承载最终成果。
- 飞书式项目空间承载协作与成员。
- Codex 式执行状态承载 AI 工作过程。
- GitHub 式标签系统承载状态、风险、证据和责任。

## 2. 视觉关键词

- 临床可信
- 安静留白
- 文档中心
- 对话驱动
- 可执行
- 可签核
- 可追溯
- 低装饰

禁止方向：

- 深色工程控制台作为默认界面。
- 大面积渐变、光斑、玻璃拟态。
- 营销式 hero 构图。
- 彩色卡片堆叠。
- 过度圆角和厚阴影。
- 一屏展示全部代码、日志、任务图和证据。

## 3. 色彩系统

### 3.1 基础色

Galen 的基础色应接近原型图：白色主画布、极浅灰背景、细边框和低饱和医疗绿。

| Token | 用途 | 建议值 |
| --- | --- | --- |
| `--color-canvas` | 文档画布、主内容背景 | `#ffffff` |
| `--color-app-bg` | 应用整体背景 | `#f7f9f8` |
| `--color-sidebar-bg` | 左侧项目栏 | `#f4f8f6` |
| `--color-panel-bg` | 侧栏、面板、卡片 | `#ffffff` |
| `--color-panel-subtle` | 轻量分区、输入框背景 | `#fafbfa` |
| `--color-border` | 主边框 | `#dfe7e3` |
| `--color-border-subtle` | 分割线、表格线 | `#edf2ef` |

使用规则：

- 主界面以白色和极浅灰为主，不使用米黄作为主基底。
- 面板和画布通过细边框区分，少用阴影。
- 阴影只用于浮层、菜单、弹窗和选区操作菜单。

### 3.2 文本色

| Token | 用途 | 建议值 |
| --- | --- | --- |
| `--color-text-primary` | 标题、正文重点 | `#13241f` |
| `--color-text-secondary` | 正文辅助信息 | `#52645e` |
| `--color-text-tertiary` | 时间、说明、占位 | `#8a9892` |
| `--color-text-disabled` | 不可用状态 | `#b8c3be` |
| `--color-text-inverse` | 深色按钮文字 | `#ffffff` |

使用规则：

- 正文不使用纯黑。
- 医学科研文档正文应清晰、低疲劳，避免浅灰过度导致可读性下降。
- 顶部品牌 `Galen` 使用更深的品牌绿，形成稳定识别。

### 3.3 品牌色与主操作

| Token | 用途 | 建议值 |
| --- | --- | --- |
| `--color-brand` | Galen 标识、核心强调 | `#006b5a` |
| `--color-brand-dark` | 主按钮 hover、深色强调 | `#005244` |
| `--color-brand-soft` | 选中项目、轻量背景 | `#e7f2ef` |
| `--color-brand-border` | 轻量选中边框 | `#a9d2c8` |

使用规则：

- 主操作按钮使用品牌绿，例如 `接受修订`、`批准执行`。
- 品牌绿只用于真正的主路径动作，不用于普通装饰。
- AI 运行中状态使用品牌绿小圆点和进度条。

### 3.4 语义色

| Token | 用途 | 建议值 |
| --- | --- | --- |
| `--color-info` | 信息、文档标签、普通证据 | `#2563eb` |
| `--color-info-soft` | 信息标签背景 | `#eff6ff` |
| `--color-success` | 已关联、已完成、可复现 | `#047857` |
| `--color-success-soft` | 成功标签背景 | `#ecfdf5` |
| `--color-warning` | 待签核、需确认 | `#c46a17` |
| `--color-warning-soft` | 待签核背景 | `#fff7ed` |
| `--color-danger` | 风险、错误、阻塞 | `#c2413b` |
| `--color-danger-soft` | 风险背景 | `#fef2f2` |
| `--color-neutral-tag` | 普通阶段标签 | `#5f6f68` |
| `--color-neutral-tag-soft` | 普通标签背景 | `#f3f6f5` |

使用规则：

- 琥珀色只用于 `待签核`、`待确认`、`风险提醒`，不要当主品牌色使用。
- 蓝色用于文档、证据、外部引用、链接类对象。
- 绿色用于 AI 运行、已完成、证据已关联、批准继续。
- 红色只用于错误、阻塞、结论越界、伦理风险等高风险提示。

## 4. 布局体系

### 4.1 全局结构

Galen 使用稳定的四区骨架：

1. 顶部栏：品牌、当前产品态、模式、AI 状态、通知、用户。
2. 左侧项目栏：课题列表、搜索、工作区、基础导航。
3. 主工作区：根据模式展示执行线程或日常目标。
4. 右侧检查区：证据链、版本记录、协作者或 AI 执行摘要。

底部提供折叠抽屉：

- `任务图`
- `代码`
- `日志`
- `证据`
- `版本`
- `产物`

### 4.2 宽度建议

| 区域 | 建议宽度 |
| --- | --- |
| 左侧项目栏 | `248px - 264px` |
| 科研执行线程 | `430px - 520px` |
| 文档画布 | 自适应，最小 `520px` |
| 右侧检查区 | `300px - 340px` |
| 日常态右侧 AI 区 | `340px - 380px` |
| 顶部栏高度 | `64px - 68px` |
| 底部抽屉高度 | 折叠态 `56px` |

### 4.3 两种核心布局

#### 科研执行线程态

用于图 1 对应场景：

- 左侧：当前课题和导航。
- 中左：科研执行线程。
- 中右：文档画布。
- 右侧：证据链、版本记录、协作者。
- 底部：任务图、代码、日志、证据、版本。

这个状态强调“对话与修订是一体的”。AI 的计划、修订建议、证据关联和签核都出现在执行线程中。

#### 日常科研工作台态

用于图 2 对应场景：

- 左侧：我的课题。
- 中间：当前目标、阶段进度、正在执行、最近产物。
- 右侧：AI 运行状态、下一步建议、等待签核。
- 底部：任务图、代码、日志、证据、产物。

这个状态强调“安静常驻”。默认不显示聊天细节和完整文档修订，用户只需知道当前目标、AI 正在做什么、哪些事项需要确认。

## 5. 组件体系

### 5.1 顶部栏

顶部栏必须克制，不能变成复杂工具条。

内容顺序：

1. `Galen` 品牌。
2. 当前产品态：`对话驱动科研协作` 或 `日常科研工作台`。
3. 模式选择：例如 `医学科研`。
4. AI 状态：例如 `AI 运行中`。
5. 通知、帮助、用户菜单。

视觉要求：

- 高度约 `64px`。
- 白底。
- 底部分割线。
- 品牌文字使用品牌绿。
- AI 状态使用小绿点 + 文字，不使用大徽章。

### 5.2 左侧项目栏

左侧栏是工作区导航，不是功能大全。

必须包含：

- 当前课题或我的课题。
- 搜索框。
- 课题列表。
- 工作区选择。
- 基础入口：概览、文档、任务、数据与代码、证据库、结果与产物。
- 设置和折叠。

课题项结构：

- 文档/课题图标。
- 课题标题。
- 当前状态，例如 `进行中`、`方案设计`、`数据清洗`、`已归档`。
- 可选更多菜单。

选中项使用品牌绿浅背景，不使用强色块。

### 5.3 科研执行线程

科研执行线程是 Galen 的核心，不应被普通聊天面板取代。

线程元素：

- 用户请求。
- AI 理解确认。
- 执行计划。
- 修订建议。
- 证据关联。
- 待签核卡片。
- 输入框。

待签核卡片必须包含：

- 签核原因。
- 主按钮：`接受修订`、`批准执行`。
- 次按钮：`查看依据`、`预览方案`。
- 说明：可提出修改意见或要求重新生成。

线程语言：

- 使用正式科研表达。
- 不使用拟人化、营销化或过度情绪化文案。
- 避免“我帮你搞定了”这类口语。

### 5.4 文档画布

文档画布借鉴 Word，但要更适合 AI 协作。

结构：

- 文档标题。
- 标签行。
- 工具栏。
- 正文章节。
- 选区高亮。
- 浮动 AI 修订菜单。
- 页脚状态：字数、保存时间、缩放。

文档标签行示例：

- `队列定义`
- `统计方案`
- `证据链已关联`
- `方法学草稿`
- `论文草稿`

选区规则：

- 选中文本使用浅蓝高亮和蓝色边框。
- 选区旁出现小型操作柄。
- 浮层菜单标题为 `AI 修订`。
- 操作项包括 `润色表达`、`补充依据`、`改写为统计语言`、`生成替代版本`、`解释此段落`。

### 5.5 右侧检查区

图 1 中右侧检查区包含：

- `证据链`
- `版本记录`
- `协作者`

图 2 中右侧区域包含：

- `AI 主驾驶` 或更正式的 `AI 执行状态`
- `正在执行`
- `下一步建议`
- `等待签核`

规范建议：

- 面向日常工作台可以使用 `AI 主驾驶` 作为区块标题。
- 面向正式科研线程时，优先使用 `AI 执行状态`、`执行计划`、`待研究者确认`。
- 右侧区只显示摘要和检查信息，不承载主对话。

### 5.6 底部折叠抽屉

底部抽屉体现 Galen 的深层能力，但默认折叠。

抽屉项：

- `任务图`
- `代码`
- `日志`
- `证据`
- `版本`
- `产物`

视觉要求：

- 单行横向排列。
- 图标 + 文本 + 展开箭头。
- 每项之间使用细分割线。
- 默认高度不超过 `56px`。
- 不使用彩色背景。

## 6. 标签体系

Galen 标签借鉴 GitHub label，但必须适配医学科研。

### 6.1 标签视觉

标签使用小圆角胶囊或圆角矩形：

- 高度：`24px - 28px`。
- 圆角：`6px`。
- 字号：`12px - 13px`。
- 边框：同色低透明度边框。
- 背景：低饱和浅色。

### 6.2 标签类型

| 类型 | 示例 | 颜色 |
| --- | --- | --- |
| 阶段 | `队列定义`、`统计方案`、`方法学草稿` | 中性蓝灰 |
| 状态 | `进行中`、`待确认`、`已归档` | 根据状态 |
| 证据 | `证据链已关联`、`引用待核验` | 绿色或蓝色 |
| 风险 | `样本量风险`、`结论越界` | 琥珀或红色 |
| 责任 | `张医生`、`统计师`、`通讯作者待审` | 中性灰 |
| 执行 | `代码已生成`、`脚本已运行` | 绿色 |

### 6.3 状态标签规则

- `进行中`：绿色点 + 绿色文字。
- `待确认`、`待签核`：琥珀色。
- `已完成`、`已接受`：绿色。
- `已归档`：灰色。
- `已阻塞`、`风险`：红色。

## 7. 状态与反馈

### 7.1 AI 运行状态

AI 运行状态必须清晰但不吵。

状态示例：

- `AI 运行中`
- `正在执行`
- `预计剩余 6 分钟`
- `等待研究者确认`
- `数据清洗已完成`

视觉规则：

- 运行中使用品牌绿点和细进度条。
- 等待确认使用琥珀标签。
- 错误或阻塞使用红色标签和简短说明。
- 不使用夸张动画。

### 7.2 进度条

进度条用于 AI 执行、数据清洗、代码运行、导出。

样式：

- 高度 `4px - 6px`。
- 轨道使用浅灰。
- 进度使用品牌绿。
- 数字百分比放在右侧，不压在线条上。

### 7.3 待签核

待签核是医学科研场景的关键状态。

签核卡片应包含：

- 需要确认的对象。
- 来源步骤。
- 影响说明。
- 主按钮。
- 查看依据入口。

颜色：

- 背景使用 `--color-warning-soft`。
- 边框使用浅琥珀。
- 主操作仍使用品牌绿。

## 8. 字体与排版

字体：

- 中文优先使用系统无衬线：`Microsoft YaHei UI`, `PingFang SC`, `Noto Sans CJK SC`, `Segoe UI`, `system-ui`。
- 代码使用 `JetBrains Mono`, `Cascadia Code`, `Consolas`。

字号：

| 用途 | 字号 |
| --- | --- |
| 品牌 | `28px - 32px` |
| 页面标题 | `18px - 20px` |
| 区块标题 | `15px - 16px` |
| 正文 | `14px` |
| 辅助文字 | `12px - 13px` |
| 标签 | `12px` |

排版规则：

- 字间距保持 `0`，不使用负字距。
- 行高正文使用 `1.55 - 1.7`。
- 文档正文应比应用 UI 更宽松。
- 控件文字不使用过大字号。

## 9. 间距、圆角、阴影

间距：

- 基础网格：`4px`。
- 面板内边距：`20px - 24px`。
- 大区块间距：`24px - 32px`。
- 列表行高：`44px - 56px`。

圆角：

- 输入框、按钮、标签：`6px`。
- 面板和卡片：`8px`。
- 头像、状态点：圆形。

阴影：

- 默认面板不使用阴影，只用边框。
- 浮动菜单使用轻阴影。
- 弹窗使用中等阴影。

## 10. 交互规则

### 10.1 默认态优先

默认态只呈现当前目标、正在执行、下一步建议、待签核和最近产物。不要默认展示完整任务图、代码和日志。

### 10.2 选区优先于命令栏

当用户选中文档或数据内容时，优先出现上下文 AI 菜单，而不是让用户去聊天框重新描述。

### 10.3 对话和执行一体

AI 的计划、修订、证据、签核不应散落在多个独立面板。它们应进入科研执行线程，形成可追溯历史。

### 10.4 右侧区只做检查

右侧区用于证据链、版本、协作者、AI 执行摘要，不作为第二个聊天主界面。

### 10.5 标签贯穿全部对象

标签应出现在课题、执行线程、文档段落、证据、任务、产物和版本上，并支持筛选。

## 11. 当前代码迁移建议

现有 `tokens.css` 已经具备设计 token 基础，但需要调整：

- 将主背景从偏米白调整为白色和极浅临床灰。
- 将当前橙色 `--accent` 降级为 warning/approval，不再作为主品牌色。
- 引入品牌绿作为主操作色。
- 增加标签语义 token：phase、status、evidence、risk、owner、execution。
- 将 `AI 主驾驶` 区块和 `科研执行线程` 区块作为明确组件。
- 将底部抽屉组件化，统一 `任务图 / 代码 / 日志 / 证据 / 版本 / 产物`。

建议后续实现顺序：

1. 更新 `tokens.css` 色彩 token。
2. 更新按钮、标签、状态点、进度条样式。
3. 重构 shell 布局为两种态：`execution-thread` 和 `daily-workbench`。
4. 实现文档选区高亮和 AI 修订浮层。
5. 实现证据链、版本记录、协作者检查区。
