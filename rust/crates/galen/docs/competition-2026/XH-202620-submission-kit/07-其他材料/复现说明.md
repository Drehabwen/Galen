# 复现说明

## 1. 环境

在仓库根目录执行。建议使用 Windows 10/11、Rust stable、Node.js 18+ 和 npm。

```powershell
git clone --branch galen-research-workbench https://github.com/Drehabwen/Galen.git
cd Galen
```

如果已经下载仓库，确认当前提交为 `3a179fb` 或更新版本即可。

## 2. 基础工程检查

```powershell
cd rust
cargo check --workspace
cargo test -p galen --lib
cd ..\rust\crates\galen
npm ci
npx tsc --noEmit
```

基础检查关注三项：

- Rust 工作区能否编译；
- Galen 核心库测试是否通过；
- React/TypeScript 前端是否能够通过类型检查。

## 3. 配对任务包

配对任务位于 `paired-benchmark/`，共 15 张任务卡：

- `PCTX01-PCTX05`：上下文保持、修订、范围切换、干扰和文件事实；
- `PTOOL01-PTOOL05`：读写、证据任务、跨文件、失败恢复和交付产物；
- `PDATA01-PDATA05`：字段规范、质量检查、时间轴、冲突来源和溯源。

运行口径写在 `paired-benchmark/README.md` 和 `paired-benchmark/cases/README.md` 中。每次运行使用相同模型、相同任务卡和相同固定输入，只替换待比较的上下文或工具编排策略。

## 4. 需要记录的指标

每个任务至少记录：

| 指标 | 记录方式 |
|---|---|
| 任务成功率 | 是否满足任务卡中的 facts、artifacts 和输出要求 |
| 工具调用数 | `tools.calls` 总数 |
| 重复调用 | 同一工具、同一参数的重复次数 |
| Token | 输入与输出 token |
| 时延 | 首次响应时间和端到端完成时间 |
| 交付状态 | 是否产生可打开的文件或链接 |
| 证据覆盖 | 结论能否回到数据、任务节点或文献来源 |

## 5. 复现原则

```text
固定任务卡
  + 固定输入
  + 固定模型
  + 固定重复次数
  -> 只改变一个系统变量
  -> 输出原始记录
  -> 用同一套指标比较
```

不要把人工印象分和自动判定混在一起。任务卡中的 `facts`、`artifacts`、`tools` 和 `tool_sequence` 是自动判定条件；人工体验记录放在 `06—效果验证报告`。
