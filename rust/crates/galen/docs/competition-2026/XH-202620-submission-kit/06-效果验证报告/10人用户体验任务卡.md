# Galen 10 人用户体验与人工一致性任务卡

版本：v1.0  
用途：比赛效果验证、真实目标用户反馈、人工一致性对照

## 一、不要把这次活动做成“自由试玩”

这 10 个人要完成的是同一组受控任务。每个人使用同一版 Galen、同一份脱敏 RehabID 队列、同一组问题。这样才能比较：

- 任务是否完成；
- 花了多长时间；
- 系统结论是否被用户认为正确；
- 哪些地方需要人工补充或纠正。

## 二、人员分组

如果当前能找到的 10 人都是本科生，仍然可以开展，但要准确命名证据：他们代表的是**真实的学生科研用户/运动康复学习者**，不代表临床专家或专业判断金标准。

| 组别 | 人数 | 主要用途 |
|---|---:|---|
| 有科研/项目经验的本科生 | 3–4 人 | 评价研究范围、数据解释和论文产物是否可理解、可复核 |
| 普通本科生用户 | 6–7 人 | 评价首次上手、理解成本、操作效率和继续使用意愿 |

优先选择运动康复专业、做过课程论文/大创/科研训练的学生。每个人记录年级、专业和是否有科研经验，不必收集真实姓名。

如果比赛材料需要更强的“人工判断一致性”，再额外邀请 2–3 名教师、研究生、康复师或科研助理做独立复核。没有这组人时，文档中应写“学生科研用户一致性”，不要写“临床专业判断一致性”。

## 三、统一测试环境

- Galen：同一提交版本；
- 数据：同一脱敏运动疲劳队列，包含多个 RehabID 和多个时间点；
- 模型配置：保持一致；
- 任务输入：使用下面的固定问题，不临时改写；
- 记录方式：系统日志 + 每个任务结束时截图；如参与者同意，再录屏。

参与者不应看到系统的 PASS/FAIL 断言，也不应先看到标准答案。

## 四、单人 25 分钟流程

### 0. 开场说明（3 分钟）

只告诉参与者：

> 这是一个面向康复科研的数据工作台。请你按自己的理解完成三个研究任务。我们测试的是系统是否帮助你完成工作，不测试你的知识水平。

不要先讲“RehabID”“PI Agent”这些内部术语。

### 1. 任务 A：继续一个已有研究（6 分钟）

输入：

> 请继续当前运动疲劳恢复研究。先告诉我当前项目研究什么、已经有哪些数据、下一步最应该做什么。

记录：

- 是否正确识别当前研究范围；
- 是否使用已导入的队列事实；
- 是否提出可执行的下一步；
- 从输入到首个可用结果的时间。

### 2. 任务 B：数据清洗和变化解释（8 分钟）

输入：

> 请检查这组 RehabID 的多时间点数据，指出缺失、异常、单位或时间问题，再比较基线、负荷后和恢复期的变化，并说明每个结论依据哪些字段。

记录：

- 数据质量问题是否被发现；
- 是否区分原始值和派生值；
- 是否指出结论对应的数据字段；
- 用户是否能理解结果，不需要反复追问。

### 3. 任务 C：生成可交付产物（6 分钟）

输入：

> 根据刚才的分析生成论文级结果摘要或 PDF，并列出可以打开验证的文献、数据和分析来源。

记录：

- 是否生成可打开的产物；
- PDF/预览是否清晰；
- 引用或来源链接是否可验证；
- 用户是否认为产物可以继续修改或交给老师。

### 4. 反馈（2 分钟）

让用户回答：

1. 最有价值的功能是什么？
2. 哪一步最浪费时间？
3. 哪个结果你不敢直接相信？为什么？
4. 如果只能改一个地方，你希望改什么？
5. 你愿不愿意继续使用？

## 五、记录表

每个参与者一张记录表，文件名建议：`user-01.md`、`user-02.md` ……

| 指标 | 记录 |
|---|---|
| 用户编号/身份类别 |  |
| 是否首次使用 |  |
| 任务 A 用时/是否完成 |  |
| 任务 B 用时/是否完成 |  |
| 任务 C 用时/是否完成 |  |
| 是否能打开 PDF |  |
| 是否能打开来源链接 |  |
| 最有价值功能 |  |
| 最大障碍 |  |
| 是否愿意继续使用 |  |

有科研/项目经验的学生组填写 0–2 分量表时，评价的是“研究任务和产物是否合理、可理解、可复核”，不是临床诊断正确性：

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 当前范围遵循 | 错误 | 部分正确 | 完全正确 |
| 核心事实保留 | 关键事实缺失 | 部分保留 | 完整保留 |
| 数据解释合理 | 无法理解/明显矛盾 | 部分理解或需修改 | 基本可理解、可复核 |
| 产物可交付 | 不可用 | 需明显修改 | 可直接核验 |

## 六、最终汇总指标

对 10 人汇总：

- 总任务完成率；
- A/B/C 各任务完成率；
- A/B/C 平均用时和中位用时；
- PDF 成功生成率；
- 来源链接成功打开率；
- 有科研经验学生组四个维度平均分；
- 系统断言与人工判断一致率；
- 分歧案例数量及截图；
- 愿意继续使用的比例。

## 七、实际执行规则

1. 不要在参与者操作时替他点击；只能解释页面入口。
2. 如果参与者卡住，记录“卡住发生在哪一步”，不要直接替他完成。
3. 所有用户使用同一数据和同一问题，不能为了让结果好看临时换任务。
4. 失败也要保留，失败案例比单纯成功截图更有说服力。
5. 只使用脱敏或构造数据，不让参与者输入真实患者信息。
