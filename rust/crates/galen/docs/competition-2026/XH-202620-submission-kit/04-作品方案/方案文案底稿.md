# Galen Rehab Intelligence｜评委版方案文案底稿

## 1. 一句话定位

Galen 面向康复科研团队，把分散在工作台、量表、传感器和实验记录中的脱敏数据接入同一研究上下文，完成数据治理、纵向分析、证据追溯和论文交付。

## 2. 评委先看到的问题

康复研究往往不是没有数据，而是数据分散、字段不一致、时间点难对齐，研究者需要在多个软件之间反复搬运并人工整理。常规对话式助手能给建议，却不能持续掌握项目状态、直接调用数据或交付可复核的结果。

## 3. 我们的解法

以项目为中心，以 RehabID 为脱敏数据身份，把“接入—清洗—对齐—分析—引用—交付”串成一条可复现链路。PI 对话负责提出研究任务，连接器负责从现有康复师工作台取得数据，Context Engine 负责维护研究范围、已确认事实和归档决策。

## 4. 现场 Demo 主线

打开脱敏队列 → 连接器发现 RehabID → 确认导入 → PI 发起数据质检和运动疲劳分析 → 展示多时间点变化 → 逐条打开数据/文献来源 → 生成正式论文 PDF → 全文预览。

## 5. 技术方案

- **统一数据层**：将 CSV、JSON、量表和设备记录映射到统一 RehabID 与时间轴；
- **上下文引擎**：区分当前研究范围、保留事实与归档范围，支持连续多轮任务；
- **证据链**：每个关键建议绑定数据字段、任务轨迹、生成时间和可打开的文献链接；
- **交付层**：生成可下载、可预览的正式 PDF，并保留源数据、处理步骤和复现入口。

## 6. 已有运行证据

上下文引擎 40/40 自动测试通过；连续约束修订 9/9 通过（55.998 秒）；运动疲劳范围切换 8/8 通过（33.000 秒）。已有真实工作台—连接器—RehabID—论文预览视频和技术佐证报告。

## 7. 创新与可复制性

创新点不在于再做一个聊天窗口，而在于把康复科研的项目状态、数据来源和交付结果组织成可计算对象。接入新的工作台、力台、Dynamo、量表或传感器时，只需增加连接器和字段映射，核心上下文与证据链保持不变。

## 8. 评测与推广

由至少 2 名真实目标用户独立完成 3 个典型问题，记录完成率、用时、人工评分、引用可打开率和 PDF 交付成功率。首个落地场景为运动疲劳科研，后续可复制到卒中、骨科和老年康复研究。
